# 第四周任务分配

这周的定位是：**完成模块 B 和模块 C 的完整首版交付**。  
如果第三周已经完成课程清单、教学班、学生名单、毕业要求指标点和支撑矩阵，那么第四周就不能只停留在“课程大纲配置”层面，而必须正式进入**面向计算链路的实现阶段**。

结合 [第二周至第八周总体任务规划.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第二周至第八周总体任务规划.md)、[第三周任务分配.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第三周任务分配.md)、[软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md)、[系统总体架构设计.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/系统总体架构设计.md) 和 [核心计算引擎说明.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/核心计算引擎说明.md)，第四周必须完成两件核心事情：

- 把**课程目标、内部权重 `w`、考核点与课程目标映射**做成可配置、可校验、可保存的模块 B 能力
- 把**动态成绩模板、原始成绩导入、课程级达成度计算、专业级达成度汇总**做成可联调、可落库、可验证的模块 C 首版

这周结束后，平台应具备进入第五周模块 D 的前置条件。换句话说，第五周报表和穿透台账的开发，必须建立在第四周已经稳定落地的**课程级计算结果、专业级汇总结果及其年级隔离口径**之上。

## 角色对应说明

根据 [软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md)，第四周涉及功能与角色的对应关系如下：

- **系统管理员**：不作为第四周核心业务角色，主要继续负责全局基础字典、账号权限体系和运行环境稳定，不承担课程配置、成绩导入和达成度计算主流程
- **教务管理人员**：负责提供课程、教学班、学生名单等上游数据，参与成绩导入链路与专业级汇总联调
- **专业负责人**：负责基于第三周已完成的毕业要求、指标点和支撑矩阵，参与专业级达成度汇总触发与结果校验
- **课程主讲教师**：第四周核心操作角色，负责课程目标、内部权重 `w`、考核点、成绩模板生成、原始成绩导入和课程级计算

## 一、本周开发基线与约束

### 1. 当前代码与阶段起点

默认第三周已经完成：

- 课程管理、教学班管理、学生名单、导入链路第一版
- 毕业要求、指标点和支撑矩阵第一版
- 宏观支撑矩阵与总支撑权重 `W` 校验第一版
- 第三周相关页面、接口和数据库字段初步对齐

第四周是在此基础上继续推进，不再回头重复做模块 A 的普通 CRUD 和基础导入。

### 2. 第四周范围边界

本周**必须完成**：

- 课程目标配置第一版
- 课程目标对毕业要求指标点内部权重 `w` 配置第一版
- 考核点与课程目标映射第一版
- 动态成绩模板生成与导出第一版
- 原始成绩导入、预览、校验、保存第一版
- 课程级达成度计算第一版
- 专业级指标点达成度汇总第一版
- 课程级和专业级状态查看与联调
- 年级隔离校验第一版

功能角色对应：

- 课程目标、内部权重 `w`、考核点、成绩模板、成绩导入、课程级计算：**课程主讲教师**
- 专业级汇总与结果校验：**专业负责人**
- 教学班和学生名单数据支撑、成绩导入上游支撑：**教务管理人员**

本周**可以启动，但不要求全部完成**：

- 课程级结果可视化细节优化
- 专业级看板交互优化
- 第五周报表接口预留

本周**不追求完成**：

- 课程级报表导出
- 专业级报告导出
- 穿透式台账导出
- 答辩展示层美化

### 3. 年级字段约束

第四周是第一周真正进入“年级口径参与计算链”的阶段，因此所有开发任务都必须显式遵守以下约束：

- `gradeYear` 表示培养方案版本或入学届别，不等于 `term`
- 模块 B 配置必须建立在当前课程所属 `专业 + 年级` 版本之上
- 模块 C 的成绩导入、课程级计算、专业级汇总都必须保持 `专业 + 年级 + 学期` 口径一致
- 不能把不同年级的毕业要求、指标点、支撑矩阵、教学班学生和成绩数据混算
- 开发中必须直接关注以下对象：
  - `graduation_requirement.grade_year`
  - `course_major.grade_year`
  - 支撑矩阵按 `majorId + gradeYear`
  - 教学班与成绩、计算结果链路中的 `gradeYear`

## 二、第四周总目标

1. 完成模块 B 第一版真实落地
2. 完成模块 C 第一版真实落地
3. 让课程主讲教师能够在当前 `专业 + 年级` 版本下配置课程目标、内部权重 `w` 和考核点
4. 让课程主讲教师能够生成动态成绩模板、导入成绩并触发课程级计算
5. 让专业负责人能够在课程级结果完整的前提下触发专业级指标点达成度汇总
6. 完成一次“教师配置 -> 模板生成 -> 成绩导入 -> 课程级计算 -> 专业级汇总”的完整联调
7. 完成一次“同一专业两个年级并存但互不串线”的隔离验证

## 三、第四周任务与核心计算引擎的关系

根据 [核心计算引擎说明.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/核心计算引擎说明.md)，系统中有两类权重：

- `W`：课程对毕业要求指标点的**宏观总支撑权重**，第三周由专业负责人在支撑矩阵中配置
- `w`：课程目标对毕业要求指标点的**课程内部贡献权重**，第四周由课程主讲教师在课程大纲配置中维护

第四周解决的是第二类权重 `w` 和完整计算链问题，并完成以下能力：

- 明确某课程在某专业某年级版本下有哪些课程目标
- 明确本课程支撑哪些毕业要求指标点，这一范围来自第三周已完成的宏观支撑矩阵
- 明确每个课程目标对这些指标点的内部贡献权重 `w`
- 保证同一指标点下相关课程目标的 `w` 之和为 `1.0`
- 明确每个考核点的满分及其唯一绑定的课程目标
- 基于教学班学生名单和考核点配置生成动态成绩模板
- 基于导入的原始成绩计算课程目标达成度、课程级指标点达成度和专业级指标点达成度

第四周生成的数据将直接服务第五周链路：

```text
第四周：课程目标 + 内部权重 w + 考核点 + 原始成绩 + 课程级结果 + 专业级结果
第五周：课程级报表 -> 专业级报告 -> 穿透式台账导出
```
