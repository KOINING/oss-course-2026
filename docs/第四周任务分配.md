# 第四周任务分配

第四周的定位是：**完成模块 B，并同步完成模块 C 的 C-1 动态模板生成与导出**。  
根据 [第二周至第八周总体任务规划.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第二周至第八周总体任务规划.md)，第四周不再只是课程大纲配置周，而是要把“课程目标、内部权重、考核点”与“原始成绩录入模板生成”连成一条可用链路，使第五周可以直接进入成绩回导、课程级计算和专业级计算。

结合 [软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md)、[第三周任务分配.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第三周任务分配.md) 和 [核心计算引擎说明.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/核心计算引擎说明.md)，第四周必须完成四件核心事情：

- 把**课程目标 `CourseObjective`** 做成课程主讲教师可维护的真实页面与接口
- 把**课程目标到毕业要求指标点的内部贡献权重 `w`** 做成可配置、可校验、可保存的第一版
- 把**考核点 `AssessmentPoint` 与唯一课程目标绑定关系** 做成可维护的第一版
- 把**C-1 动态成绩模板生成与导出**做成可下载、可预览、可校验前置条件的第一版

本周结束后，平台至少应打通：

```text
教师选择教学班/课程
-> 配置课程目标
-> 配置内部贡献权重 w
-> 配置考核点
-> 系统校验模块 B 完整性
-> 生成并下载原始成绩录入模板
```

## 角色对应说明

根据需求说明书，第四周涉及功能与角色的对应关系如下：

- **系统管理员**：不是第四周核心业务角色，仅继续保障账号、角色和基础字典稳定
- **教务管理人员**：不是主操作角色，但需保证教学班、学生名单、课程归属数据能支撑模板生成
- **专业负责人**：不是主操作角色，但其第三周配置的宏观支撑矩阵 `W` 是教师端配置 `w` 的上游约束
- **课程主讲教师**：第四周核心角色，负责课程目标、内部贡献权重 `w`、考核点、动态成绩模板生成与导出

8. 为第五周 C-2、C-3、C-4 提供稳定数据口径

## 三、第四周任务与核心计算引擎的关系

核心计算引擎中有两类权重：

- `W`：课程对毕业要求指标点的**宏观总支撑权重**，第三周由专业负责人在支撑矩阵中配置
- `w`：课程目标对毕业要求指标点的**课程内部贡献权重**，第四周由课程主讲教师在课程大纲配置中维护

第四周仍不做达成度计算，但必须完成第五周计算的全部前置数据：

- 明确本课程有哪些课程目标
- 明确本课程支撑哪些毕业要求指标点，这一范围来自第三周的宏观支撑矩阵
- 明确每个课程目标对这些指标点的内部贡献权重
- 保证同一毕业要求指标点下，所有相关课程目标的 `w` 之和为 `1.0`
- 明确每个考核点的满分，以及它唯一绑定到哪个课程目标
- 根据教学班学生名单和考核点配置生成原始成绩录入模板

第四周生成的模板必须直接服务第五周链路：

```text
第四周：学生名单 + 考核点配置 -> 动态成绩模板
第五周：成绩模板回导 -> student_assessment_score -> 课程目标达成度 -> 课程级指标点达成度 -> 专业级达成度
```
