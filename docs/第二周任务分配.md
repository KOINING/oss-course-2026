# 第二周任务分配

这周的定位是：**从“认证骨架周”进入“真实业务落地周”**。  
第一周已经基本完成工程搭建、登录鉴权、角色菜单和管理员账号管理入口；第二周不再以占位页和基础框架为目标，而是要正式把**模块 A 的第一批真实业务能力做出来**。

结合当前代码状态和 [第二周至第八周总体任务规划.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第二周至第八周总体任务规划.md)，第二周必须完成两件核心事情：

- 把**基础字典、毕业要求、指标点**做成可用的前后端闭环
- 把**管理员账号与角色管理**稳定下来，作为后续全角色联调入口

## 一、本周开发基线与约束

### 1. 当前代码已具备的基础

- 前端基础工程、登录页、后台 Layout、首页、404 已完成
- token 存储、用户信息恢复、角色菜单已完成
- 管理员“账号与角色管理”前后端页面和接口已接入
- 后端已有 JWT 登录、统一返回、全局异常、健康检查
- 后端已有管理员账号管理接口：
  - `/api/admin/listUsers`
  - `/api/admin/listAssignableRoles`
  - `/api/admin/addUser`
  - `/api/admin/updateUser`
  - `/api/admin/updateUserStatus`
- 数据库已有较完整业务表设计稿，MySQL 已接入

### 2. 第二周范围边界

本周**必须完成**：

- 学年学期管理
- 学院管理
- 专业管理
- 课程基础信息管理
- 毕业要求管理
- 指标点管理
- 管理员账号与角色管理联调稳定化

本周**可以启动，但不要求全部完成**：

- 模块 A 通用表格与弹窗表单组件抽象
- 第三周宏观支撑矩阵的页面原型
- 班级/学生数据结构预留

本周**不追求完成**：

- 宏观支撑矩阵配置闭环
- 课程目标、内部权重、考核点
- Excel 成绩模板生成
- 达成度计算
- 报表导出

## 四、第二周并行开发原则

第二周开始，除组长外，**每位成员只设置 1 个主 Issue**。  
这个 Issue 可以包含 2 到 4 个强关联子任务，但最终必须收敛为**一个完整交付目标**。

本周按**前端 3 人并行、后端 3 人并行**安排：

- 前端 3 人分别独立负责 3 组页面
- 后端 3 人分别独立负责 3 组接口对象
- 数据库 1 人统一负责字段、约束、初始化脚本和字典
- 组长负责统筹、联调、环境和验收收口
