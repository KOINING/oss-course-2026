# 前端接口文档 - 支撑矩阵配置模块

> 本文档由前端（支梦林）提供，供后端开发参考。

## 接口概述

支撑矩阵配置模块用于配置课程与毕业要求指标点之间的宏观支撑关系及总支撑权重，保证专业级达成度汇总链路完整可追踪。

- **Base URL：** `/api`
- **请求方式：** 所有接口均为 **POST**
- **请求体 / 响应体：** **JSON**
- **鉴权：** 所有接口需在 Header 中携带 `Authorization: Bearer <token>`

---

## 统一响应格式

```json
{
  "code": 200,        // 0 或 200 表示成功
  "message": "success",
  "data": {}          // 业务数据，可为对象、数组或 null
}
```

> 前端 axios 拦截器已自动解包 `data` 字段，所以下文示例中 "响应示例" 展示的是 **`data` 字段内部** 的内容。

|------|------|------|

## 二、矩阵核心接口

### 2.1 查询支撑矩阵数据

**接口地址：** `POST /supportMatrix/getSupportMatrix`

**请求参数：**

```json
{
  "majorId": 1,
  "termId": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `majorId` | long | 是 | 专业 ID |
| `termId` | long | 是 | 学年学期 ID |

**响应示例（data 内容）：**

```json
[
  {
    "courseId": 1,
    "ipId": 1,
    "weight": 0.30
  },
  {
    "courseId": 1,
    "ipId": 2,
    "weight": 0.50
  },
  {
    "courseId": 2,
    "ipId": 1,
    "weight": 0.25
  }
]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `courseId` | long | 课程 ID |
| `ipId` | long | 指标点 ID |
| `weight` | double | 总支撑权重（0~1，保留两位小数） |

**注意事项：**
- **仅返回已勾选的记录**（即 weight > 0 的行），未配置的组合不返回
- 前端根据课程列表 × 指标点列表构建完整矩阵网格，未在返回数据中的单元格默认为"未勾选、权重为 0"

---

### 2.2 保存支撑矩阵

**接口地址：** `POST /supportMatrix/saveSupportMatrix`

**请求参数：**

```json
{
  "majorId": 1,
  "termId": 1,
  "rows": [
    {
      "courseId": 1,
      "ipId": 1,
      "weight": 0.30
    },
    {
      "courseId": 1,
      "ipId": 2,
      "weight": 0.50
    },
    {
      "courseId": 2,
      "ipId": 1,
      "weight": 0.25
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `majorId` | long | 是 | 专业 ID |
| `termId` | long | 是 | 学年学期 ID |
| `rows` | array | 是 | 支撑关系列表（仅含已勾选的单元格） |
| `rows[].courseId` | long | 是 | 课程 ID |
| `rows[].ipId` | long | 是 | 指标点 ID |
| `rows[].weight` | double | 是 | 权重值，范围 (0, 1] |

**响应示例（data 内容）：** `null`（成功即可）

**注意事项：**
- 前端提交前已完成列权重合计校验（每列之和 = 1.00），后端建议做兜底校验
- 采用 **全量覆盖** 策略：后端删除该 `(majorId, termId)` 下的全部旧记录，再批量插入 `rows`
- `rows` 为空数组 `[]` 时表示清空该专业+学期的全部支撑关系，须正常处理

---

### 2.3 重置支撑矩阵（备用）

**接口地址：** `POST /supportMatrix/resetSupportMatrix`

**说明：** 当前前端使用本地快照实现"重置为上次保存状态"，不调用此后端接口。该接口为备用，可按需实现。

## 四、前端页面结构

### 4.1 页面组件

- **文件：** `src/views/requirements/SupportMatrixView.vue`
- **路由：** `/support-matrix`（名称：`SupportMatrix`）

### 4.2 功能清单

| 功能 | 说明 |
|------|------|
| 筛选栏 | 专业下拉 → 课程下拉联动 → 学年学期下拉 → 点击"查询"加载矩阵 |
| 矩阵展示 | 行为课程，列为指标点，含复选框 + 权重输入 |
| 支撑勾选 | 勾选后权重输入框激活，取消勾选自动清零 |
| 权重输入 | 步进 0.05，范围 0~1，保留两位小数 |
| 列合计行 | 实时计算每列权重之和，=1.00 显示绿色 ✓，否则红色 ✗ |
| 保存校验 | 提交前校验所有列和，不满足则提示具体指标点编号 |
| 重置按钮 | 恢复到上次保存时的本地快照（不调用后端接口） |

### 4.3 用户操作流程

1. 页面加载 → 自动请求专业列表 + 学年学期列表
2. 用户选择专业 → 自动请求该专业下的课程列表
3. 用户选择学期 → 点击"查询"
4. 前端并行请求：课程列表 + 指标点列表 + 支撑矩阵数据
5. 渲染完整矩阵 → 用户勾选/修改权重 → 点击"保存矩阵"提交

| 5 | `POST /supportMatrix/getSupportMatrix` | 查询支撑矩阵数据 | **高** |
| 6 | `POST /supportMatrix/saveSupportMatrix` | 保存支撑矩阵（全量覆盖） | **高** |

## 七、联调注意事项

1. 所有接口须进行登录鉴权（Header: `Authorization: Bearer <token>`），未登录返回 401
2. 响应 `code` 为 `0` 或 `200` 均视为成功（前端拦截器兼容两种写法）
3. 指标点列表须按 `ipCode` 升序排列，确保矩阵列顺序稳定
4. 课程列表须按 `courseCode` 或 `courseId` 升序排列
5. `getSupportMatrix` 只返回 weight > 0 的记录，空值无需返回
6. `saveSupportMatrix` 采用全量覆盖，后端不必做 diff 比对
7. 建议先联调查询链路（1→3→4→5），矩阵正常展示后再联调保存接口（6）
