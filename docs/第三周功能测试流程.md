第三周的测试目标不是重复第二周普通 CRUD 验收，而是验证以下两条业务主链是否已经形成可用闭环：

1. 教务管理人员完成课程清单、教学班、学生名单及导入链路
2. 专业负责人完成课程-毕业要求指标点宏观支撑矩阵配置及总支撑权重 `W` 校验链路

## 二、第三周测试范围

根据规划文档和当前项目实现，第三周应重点测试以下功能：

- 模块 A-3：课程体系与名单导入
  - 课程管理
  - 教学班管理
  - 学生名单管理
  - 全专业课程清单导入
  - 教学班学生名单导入
  - 导入结果预览与错误提示
- 模块 A-4：宏观支撑矩阵配置
  - 支撑矩阵页面访问
  - 专业/课程/学年学期筛选
  - 课程-指标点支撑关系勾选
  - 总支撑权重 `W` 输入与列校验
  - 权重不为 `1.0` 时禁止保存

同时补充角色边界测试，确认第三周功能只对正确角色开放：

- 系统管理员不承担第三周主业务角色，不应进入课程管理、教学班管理、学生名单管理、数据导入
- 教务管理人员应具备课程、教学班、学生名单、导入链路的完整访问权限
- 专业负责人应具备毕业要求与指标点、支撑矩阵配置权限

## 流程 A：系统管理员角色边界测试

### 目标

确认系统管理员只承担系统初始化、基础字典、账号与角色管理职责，不再承担第三周主业务链。

### 测试步骤

1. 使用 `admin / 123456` 登录系统
2. 观察左侧菜单
3. 访问 `基础数据`
4. 观察 `基础数据` 页面内容
5. 手工访问以下路径：
   - `/course-management`
   - `/teaching-class`
   - `/student-list`
   - `/data-import`

### 预期结果

1. 左侧菜单可以看到：
   - 首页
   - 基础数据
   - 系统管理
2. 左侧菜单不应看到：
   - 课程管理
   - 教学班管理
   - 学生名单管理
   - 数据导入
   - 支撑矩阵配置
3. `基础数据` 页面中只应展示：
   - 学年学期
   - 学院
   - 专业
4. 管理员手工访问第三周主业务路径时，应被路由守卫拦截回首页或无权访问

## 流程 B：教务管理人员课程管理与课程清单导入链路

### 目标

验证课程管理已经从基础数据页中剥离，形成独立菜单和独立导入主链。

### 测试步骤

1. 使用 `academic_wu / 123456` 登录
2. 点击左侧 `课程管理`
3. 验证课程列表可正常加载
4. 测试课程查询条件是否可用
5. 新增一条课程记录
6. 编辑一条已有课程记录
7. 在课程管理页点击“课程清单导入”入口
8. 跳转到 `数据导入` 页面，确认当前激活页签为“课程清单导入”
9. 点击“下载模板”
10. 核对模板字段是否为：
    - `所属专业代码`
    - `课程代码`
    - `课程名称`
    - `学分`
    - `状态`
11. 上传一份合法课程清单文件
12. 点击“开始导入”
13. 观察导入结果预览区
14. 再上传一份包含错误数据的课程清单文件

### 预期结果

1. `课程管理` 为独立菜单，不再出现在基础数据页签中
2. 课程列表、查询、新增、编辑可以调用真实接口
3. 导入入口跳转到真实导入页，不再是占位页
4. 导入页“课程清单导入”页签可以正常使用
5. 下载模板字段与规划文档一致
6. 导入成功后结果区应显示：
   - 总记录数
   - 成功条数
   - 失败条数
7. 导入失败时结果区应显示失败行和失败原因
8. 导入结果预览应挂在主操作路径内，而不是脱离导入页的独立预览页

---

## 流程 C：教务管理人员教学班与学生名单链路

### 目标

验证教学班、学生名单和教学班学生名单导入是否已经对齐到同一条业务链。

### 测试步骤

1. 使用 `academic_wu / 123456` 登录
2. 点击 `教学班管理`
3. 验证教学班列表加载、查询、新增、编辑是否正常
4. 重点检查教学班编号 `classCode` 是否作为页面可见业务字段存在
5. 点击 `学生名单管理`
6. 验证学生列表加载、查询、新增、编辑是否正常
7. 在 `教学班管理` 页点击学生名单导入入口
8. 在 `学生名单管理` 页点击学生名单导入入口
9. 确认两者都跳转到同一个导入页，且激活页签为“教学班学生名单导入”
10. 点击“下载模板”
11. 核对模板字段是否为：
    - `学号`
    - `姓名`
    - `专业代码`
    - `入学年份`
    - `教学班编号`
12. 上传一份合法学生名单文件
13. 点击“开始导入”
14. 观察导入结果预览区
15. 再上传一份包含错误数据的学生名单文件，例如：
    - 教学班编号不存在
    - 专业代码不存在
    - 学号为空

### 预期结果

1. 教学班和学生名单是两张独立管理页面
2. 教学班编号 `classCode` 贯穿页面、导入、关联链路
3. 教学班页与学生名单页的导入入口都应指向同一条真实业务链：
   - `/data-import?type=student-classes`
4. 导入结果预览应显示：
   - 总记录数
   - 成功条数
   - 失败条数
   - 失败原因
5. 错误提示应围绕模板字段给出，不能只返回笼统失败
6. 教学班学生名单导入与 `student_class` 关系建立属于同一条链路，不能出现一个页面能导入、另一个页面查不到关系数据的情况

## 流程 E：专业负责人宏观支撑矩阵配置与 `W` 校验

### 目标

验证当前活跃链路 `supportmatrix.js + requirements/SupportMatrixView.vue` 已经形成可配置、可校验、可保存的第一版闭环。

### 测试步骤

1. 使用 `director_chen / 123456` 登录
2. 点击 `支撑矩阵配置`
3. 检查页面是否存在以下筛选项：
   - 专业
   - 课程
   - 学年学期
4. 先选择一个专业，再点击“查询”
5. 观察矩阵表格是否成功加载：
   - 行为课程
   - 列为毕业要求指标点
6. 勾选若干课程与指标点之间的支撑关系
7. 对已勾选单元格填写权重 `W`
8. 故意制造一列权重和不等于 `1.00`
9. 点击“保存矩阵”
10. 观察提示信息
11. 再将该列权重调整到 `1.00`
12. 再次点击“保存矩阵”
13. 刷新页面或重新查询，验证保存结果是否回显

### 预期结果

1. 矩阵页可以正常访问，不再走旧链路
2. 查询后可以看到真实二维矩阵
3. 支撑关系可勾选，权重可输入
4. 页面底部或列合计区域应能显示每个指标点列的权重和
5. 当某指标点列权重和不为 `1.00` 时：
   - 页面应给出明确提示
   - 保存应被阻止
6. 当所有指标点列权重和均为 `1.00` 时：
   - 保存成功
   - 再次查询可以正确回显保存结果

## 九、一句话总结

第三周功能测试的关键，不是验证零散页面是否能打开，而是验证两条真实业务链是否已闭环：

- 教务管理人员：`课程管理 -> 数据导入 -> 教学班/学生名单 -> 学生名单导入`
- 专业负责人：`毕业要求与指标点 -> 支撑矩阵配置 -> W 校验 -> 保存回显`

只有这两条链路都稳定打通，第三周任务才算真正完成，并能够为第四周课程目标与内部权重 `w` 的开发提供可靠前置条件。
