# 第三周任务分配

这周的定位是：**完成模块 A 剩余关键能力，正式把“课程-毕业要求指标点宏观支撑矩阵”做起来**。  
如果第二周已经完成基础字典、毕业要求、指标点和管理员能力，那么第三周就不能继续停留在普通 CRUD 层面，而必须进入**面向计算链路的配置阶段**。

结合 [第二周至第八周总体任务规划.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第二周至第八周总体任务规划.md)、[第二周任务分配.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第二周任务分配.md)、[软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md) 和 [核心计算引擎说明.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/核心计算引擎说明.md)，第三周必须完成两件核心事情：

- 把**教学班、学生名单、导入链路**做成可用的模块 A 能力
- 把**课程-毕业要求指标点宏观支撑矩阵与总支撑权重 W** 做成可配置、可校验、可保存的第一版

这周结束后，平台应具备进入第四周模块 B 的前置条件。换句话说，第四周课程目标和内部权重 `w` 的开发，必须建立在第三周已经稳定落地的**课程-毕业要求指标点宏观支撑矩阵**及其总支撑权重 `W` 之上。

## 角色对应说明

根据 [软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md)，第三周涉及功能与角色的对应关系如下：

- **系统管理员**：不作为第三周核心业务角色，主要继续负责全局基础字典与账号权限体系的稳定，不承担名单导入和矩阵配置主流程
- **教务管理人员**：负责课程体系与名单导入链路，即教学班维护、学生名单维护、教学班学生名单导入
- **专业负责人**：负责课程-毕业要求指标点宏观支撑矩阵配置与总支撑权重 `W` 维护
- **课程主讲教师**：第三周不是主操作角色，仅作为第四周课程目标、内部权重 `w` 和考核点配置的后续承接方

## 一、本周开发基线与约束

### 1. 当前代码与阶段起点

默认第二周已经完成：

- 学年学期、学院、专业、课程管理第一版
- 毕业要求与指标点管理第一版
- 管理员账号与角色管理稳定联调
- 基础数据、毕业要求、指标点的前后端字段初步对齐

第三周是在此基础上继续推进，不再回头重复做第二周的普通 CRUD。

### 2. 第三周范围边界

本周**必须完成**：

- 教学班基础数据结构落地
- 学生名单基础数据结构落地
- 教学班/学生名单导入入口与导入结果链路第一版
- 课程与毕业要求指标点宏观支撑矩阵页面第一版
- 宏观总支撑权重 `W` 校验第一版
- 课程体系与支撑关系前后端联调

功能角色对应：

- 教学班、学生名单、名单导入：**教务管理人员**
- 宏观支撑矩阵、总支撑权重 `W` 校验：**专业负责人**

本周**可以启动，但不要求全部完成**：

- 导入错误明细优化
- 矩阵页面高密度交互优化
- 第四周课程目标模块的接口预留

本周**不追求完成**：

- 课程目标、内部权重、考核点
- 原始成绩导入
- 课程级达成度计算
- 专业级达成度计算
- 报表导出

## 二、第三周总目标

1. 完成模块 A 第二阶段真实落地
2. 完成教学班与学生名单的结构化维护或导入第一版
3. 完成课程-毕业要求指标点宏观支撑矩阵第一版
4. 完成同一毕业要求指标点下总支撑权重 `W = 1.0` 的校验能力
5. 为第四周课程目标、内部权重 `w` 开发提供稳定前置数据
6. 完成一次“教务管理员导入名单 -> 专业负责人配置矩阵 -> 系统校验权重”的联调

## 三、第三周任务与核心计算引擎的关系

根据 [核心计算引擎说明.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/核心计算引擎说明.md)，系统中有两类权重：

- `W`：课程对毕业要求指标点的**宏观总支撑权重**
- `w`：课程目标对毕业要求指标点的**课程内部贡献权重**

第三周的任务只解决第一类权重 `W`，并完成以下前置能力：

- 明确哪些课程支撑哪些毕业要求指标点
- 为每个毕业要求指标点配置所有支撑课程的总支撑权重
- 保证同一毕业要求指标点下所有课程的 `W` 之和为 `1.0`

只有第三周这一层做实，第四周教师端才能读取“本课程负责支撑哪些毕业要求指标点”，再进一步配置课程内部的 `w`。

- 支佳璇先给出字段含义、约束和样例数据说明
- 后端在此基础上落实实体、DTO、接口
- 前端根据接口字段稳定接入页面

## 十、第三周联调目标

到周末至少打通下面这条链路：

1. 教务管理员进入教学班或学生名单页面
2. 上传或录入一批学生名单数据
3. 系统返回导入结果或展示名单结果
4. 专业负责人进入课程-毕业要求指标点宏观支撑矩阵页面
5. 配置课程与毕业要求指标点支撑关系
6. 输入总支撑权重 `W`
7. 系统校验同一毕业要求指标点下的总支撑权重是否为 `1.0`

角色说明：

- 第 1 到第 3 步对应：**教务管理人员**
- 第 4 到第 7 步对应：**专业负责人**

## 十一、第三周验收标准

周末只看这些：

- 教学班与学生名单结构已落地
- 名单导入入口和后端导入接口可联调
- 宏观支撑矩阵页面可展示课程-毕业要求指标点关系
- 宏观总支撑权重 `W` 校验可用
- 第三周新增页面均已接入真实后端接口
- 第三周新增接口均有基础参数校验
- 仓库中无新的构建产物误提交
- 第三周形成规则对齐说明、联调记录和验收结论

## 十二、一句话总结

第三周的关键不是继续做普通数据维护，而是**把名单导入和课程-毕业要求指标点宏观支撑矩阵做实，把总支撑权重 `W` 的规则真正落到系统里**。  
只要这一周把教学班/学生名单和宏观矩阵做稳，第四周课程目标和内部权重 `w` 的开发就能顺利展开，计算主链也才算真正铺开。
