# 第五周任务分配

第五周的定位是：**完成模块 D 首版，把第四周已经落库的课程级结果、专业级结果转化为认证可用的报表、报告和穿透式台账输出能力。**

结合 [第二周至第八周总体任务规划.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第二周至第八周总体任务规划.md) 和 [软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md)，第五周不是继续重做第四周的“结果查看页、专业级看板、计算链路”，而是基于第四周已经完成的模块 B/C，补齐以下模块 D 能力：

- 课程级评价报表导出
- 专业级评价报告导出
- 专业级雷达图输出
- 穿透式 Excel 台账导出
- 结果查询、筛选和导出权限控制

第五周结束后，平台应具备进入第六周“全链路联调、缺陷修复和稳定化”的前置条件。

## 一、本周开发基线与约束

### 1. 当前阶段起点

默认第四周已经完成：

- 模块 B 首版闭环
- 模块 C 首版闭环
- `Cij / C̄j / Ek / Gk` 结果落库
- 课程级结果查看首版
- 专业级看板与专业级结果查看首版
- 双专业、双年级 E2E 测试数据

因此第五周**不再把“课程级结果查看页”“专业级结果查看页”“专业级看板”作为新主任务重新建设**，而是：

- 复用第四周已有结果页作为报表导出入口
- 复用第四周已有专业级结果页作为专业级报告与雷达图承载入口
- 新增模块 D 所需的导出、归档、穿透和权限控制能力

### 2. 第五周主范围

本周**必须完成**：

- 课程级评价报表导出
- 专业级评价报告导出
- 专业级雷达图首版
- 穿透式 Excel 台账导出
- 结果查询、筛选和导出权限控制
- 报表与台账的数据口径统一

本周**可以优化，但不要求作为主交付单列**：

- 第四周已有结果页的展示细节优化
- 雷达图和报表视觉样式优化
- 报表下载交互优化

本周**不追求完成**：

- 新增核心计算公式
- 重写第四周已有计算接口
- 重做第四周专业级看板首版
- 非认证主链路分析功能

### 3. 第五周核心数据依赖

第五周全部输出必须建立在第四周结果表之上，核心依赖如下：

- `student_objective_achievement`
- `course_objective_achievement`
- `course_indicator_achievement`
- `major_indicator_achievement`

任何报表、报告、台账都不能绕开这些结果表临时重算，否则会破坏第四周已确认的计算口径。

### 4. 年级与学期口径

第五周继续严格区分：

- `gradeYear`：培养方案版本 / 学生届别
- `term`：教学运行学期

因此：

- 课程级评价报表必须以 `某课程 + 某年级` 作为主体，并覆盖该课程该年级下的全部相关教学班
- 专业级评价报告必须以 `专业 + 年级` 作为主体，必要时附带当前统计学期说明
- 穿透式台账必须保证从专业级追到课程级、再追到课程目标与考核点时不串线

## 三、第五周任务与需求文档的对应关系

根据 [软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md) 第 4.4 节，模块 D 仅关注三件事：

- **D-1 课程级评价报表**
- **D-2 专业级报告**
- **D-2 穿透式台账**

对应到第五周：

这里的“评价”不是泛指页面展示，而是指**基于第四周已经完成的达成度计算结果，对课程层和专业层形成可归档、可导出、可用于认证支撑的结果性评价输出**。  
也就是说，第五周输出的“课程级评价报表”和“专业级评价报告”，本质上都是对**毕业要求达成情况**的结果表达，而不是重新做一遍计算。

### 1. 课程级评价报表

- 这里的“课程级评价”指：**针对某一门课程在某一年级培养方案版本下，评价该课程在本轮教学中对课程目标和课程级毕业要求指标点的达成情况**
- 它面向的核心问题是：
  - 该课程在当前年级版本下的各课程目标是否达到预期
  - 该课程在当前年级版本下对所支撑毕业要求指标点的达成情况如何
  - 该课程在当前年级下各教学班的结果是否一致、哪些班级存在差异
- 它使用的核心结果源是：
  - `course_objective_achievement`
  - `course_indicator_achievement`
- 导出格式至少覆盖 `Excel + PDF`
- 内容至少包含：
  - 各教学班单项平均分
  - 各课程目标达成度明细
  - 课程级指标点达成度
- 对应输出物建议统一理解为：
  - 《课程目标达成情况评价表》
  - 或课程级达成度评价报表
- 这份报表的对象边界可以统一理解为：**某课程 / 某年级**
- 该课程该年级下的多个教学班属于同一份课程级评价报表的明细范围
- 这份报表的重点不是展示原始成绩明细本身，而是把原始成绩经第四周计算后形成的课程目标级、课程级达成结果做成教师可归档的评价材料

### 2. 专业级评价报告

- 这里的“专业级评价”指：**针对某一专业、某一年级，评价该专业在当前统计范围内的毕业要求指标点整体达成情况**
- 它面向的核心问题是：
  - 该专业该年级本轮参与汇总的支撑课程，最终汇总后各指标点达成度 `Gk` 如何
  - 哪些指标点达成较好，哪些指标点相对偏弱
- 它使用的核心结果源是：
  - `major_indicator_achievement`
  - 必要时联动课程级结果表做追溯说明
- 按 `专业 + 年级` 组织报告主体，必要时在报告中标注当前统计学期
- 提供 `ECharts` 雷达图首版
- 报告内容与页面展示口径一致
- 对应输出物建议统一理解为：
  - 专业级毕业要求指标点达成度评价报告
  - 专业级认证评价报告
- 这份报告的对象边界可以统一理解为：**某专业 / 某年级**
- 这份报告的重点不是单门课表现，而是从专业整体视角，对毕业要求指标点达成情况进行汇总评价，并为认证分析和后续改进提供依据

### 3. 穿透式台账

- 支持从专业指标点向下追溯到：
  - 课程级指标点
  - 课程目标
  - 考核点
  - 原始成绩
- 导出格式以 `Excel` 为主

## 五、第五周并行开发原则

第五周继续保持：**每位成员只设置 1 个主 Issue**。  
每个主 Issue 可以包含 2 到 4 个强关联子任务，但最终必须收敛为**一个完整交付目标**。

本周按以下方式并行：

- 前端 3 人分别负责：
  - 课程级报表导出入口与报表展示承载
  - 专业级报告导出入口与雷达图承载
  - 穿透式台账导出交互与逐层下钻
- 后端 3 人分别负责：
  - 课程级报表数据装配与导出
  - 专业级报告 / 雷达图数据装配与导出
  - 穿透式台账查询与导出
- 数据库 1 人统一负责结果表字段链路、报表口径 SQL 和样例数据
- 组长负责统筹、联调、文档与周验收收口
