# 第六周任务分配

第六周的定位是：**在课程剩余两周的前提下，补齐模块 A/B/C/D 主链路缺口，完成从基础数据到报表导出的全链路联调、计算校验和缺陷修复。**

结合 [第二周至第八周总体任务规划.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第二周至第八周总体任务规划.md)、[第五周任务分配.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第五周任务分配.md) 和 [软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md)，第六周不再以新增单个模块为中心，而是围绕一条可演示业务闭环完成收口：

- 模块 A：基础数据、毕业要求、指标点、课程、教学班、学生、支撑矩阵
- 模块 B：课程目标、内部权重 `w`、考核点、考核点到课程目标映射
- 模块 C：成绩模板、原始成绩导入、课程级计算、专业级汇总
- 模块 D：课程级报表、专业级报告、雷达图、穿透式台账导出

第六周结束后，平台应具备进入第七周“部署、测试、文档、演示数据和答辩材料固化”的前置条件。

---

## 一、本周开发基线与约束

### 1. 当前阶段起点

默认第二周至第五周已经形成以下基础：

- 登录、权限、角色菜单和系统骨架
- 模块 A 的基础数据主链路
- 模块 B/C 的数据表与首版业务能力
- 模块 D 的报表、报告、雷达图和穿透台账首版能力
- 第五周形成的报表导出入口和结果表读取口径

第六周不再按模块单点继续扩张，而是把前几周成果串成完整业务链路。

### 2. 第六周主范围

本周**必须完成**：

- 模块 A/B/C/D 全链路联调
- 模块 B/C/D 主链路缺口补齐
- 六个高频管理列表的前后端分页改造：
  - 基础数据-专业管理
  - 基础数据-学院管理
  - 账号与角色管理
  - 课程管理列表
  - 教学班管理列表
  - 学生名单管理列表
- 课程级与专业级计算公式复核
- `专业 + 年级` 数据隔离验证
- 跨角色流程联调
- 阻断性缺陷修复
- 演示数据、初始化 SQL、增量 SQL 和部署依赖梳理
- 第六周测试记录与问题清单

本周**可以优化，但不作为主交付单列**：

- 页面展示细节优化
- 报表样式优化
- 下载交互细节优化
- 非阻断性体验问题优化

本周**不追求完成**：

- 新增需求规格说明书以外的业务模块
- 问卷等间接评价功能
- 成绩异常预警或真实性校验
- AI 辅助分析功能
- 大规模重构已有计算链路

### 3. 第六周核心数据依赖

第六周联调必须围绕以下主链路表和结果表展开：

- 基础数据与培养方案相关表
- 毕业要求、指标点、课程、专业、年级、教学班、学生相关表
- 课程目标、内部权重、考核点、原始成绩相关表
- `student_objective_achievement`
- `course_objective_achievement`
- `course_indicator_achievement`
- `major_indicator_achievement`

任何导出、报表和台账都应优先读取已经落库的结果表，除非本周任务明确是修复计算落库问题。

### 4. 年级与学期口径

第六周继续严格区分：

- `gradeYear`：培养方案版本 / 学生届别
- `term`：教学运行学期

因此：

- 毕业要求、指标点、课程培养方案、支撑矩阵必须按 `专业 + 年级` 区分
- 教学班、成绩导入和计算结果必须继承或显式关联 `gradeYear`
- 专业级汇总以 `专业 + 年级` 为归档主体，`term` 仅作为统计批次或结果快照说明
- 双专业、双年级样例下，配置、导入、计算、查询和导出都不能串线

1. 跑通 1 条从模块 A 到模块 D 的完整业务闭环

3. 完成课程级和专业级计算结果的手工样例复核
4. 完成跨角色流程联调和权限检查

6. 完成六个管理列表的分页查询闭环，避免大数据量列表一次性加载
7. 为第七周部署、文档、演示和答辩准备提供可冻结版本

## 三、第六周任务与总体规划的对应关系

根据 [第二周至第八周总体任务规划.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/第二周至第八周总体任务规划.md) 第四部分，第六周核心任务包括：

对应到第六周任务分配：

- 前端 3 人分别负责六个高频管理列表的前后端分页开发，每人负责 2 个页面，从 Element Plus 分页组件到后端分页接口完整收口
- 后端 3 人分别负责模块 B/C/D 接口链路、计算链路、报表台账链路问题收口，并配合分页接口口径复核
- 数据库 1 人负责年级隔离、样例数据、脚本和自检 SQL
- 组长负责全链路统筹、Issue 追踪、联调验收和第七周交接材料

### 分页接口统一口径

本周分页改造统一采用以下接口口径：

- 前端查询参数统一携带 `pageNum`、`pageSize`
- 后端列表查询接口接收分页参数，并基于筛选条件执行分页查询
- 后端返回结构统一包含：
  - `records`：当前页数据
  - `total`：符合筛选条件的总记录数
  - `pageNum`：当前页码
  - `pageSize`：每页条数
- 前端统一使用 Element Plus `el-pagination`，支持页码切换、每页条数切换和总数展示
- 前端 `pageSize` 可选项统一设置为 `5, 10, 20, 50`
- 查询、重置、新增、编辑、删除、启停后必须正确刷新当前分页数据
- 保持现有动作式接口路径不变，分页接口命名统一采用 `listXxxByPage`，不另起一套资源式接口

## 五、第六周并行开发原则

第六周继续保持：**每位成员只设置 1 个主 Issue**。  
每个主 Issue 可以包含 2 到 5 个强关联子任务，但最终必须收敛为**一个完整交付目标**。

- 前端 3 人分别负责：

### 2. `member/kwf`：毕业要求/指标点分页必要性分析与专业级看板表格滚动优化

Issue 内容：

- 对毕业要求表是否需要分页进行分析与处理：
  - 分析当前毕业要求表的数据规模、筛选条件、行合并逻辑和编辑体验
  - 判断是否需要接入分页查询
  - 若需要分页，给出分页方案并与现有 `专业 + 年级` 口径保持一致
  - 若暂不分页，需要在 Issue 结论中说明原因和替代处理方式
- 对指标点表是否需要分页进行分析与处理：
  - 分析当前指标点表的数据规模、毕业要求合并行逻辑和编辑体验
  - 判断分页是否会破坏毕业要求与指标点的层级展示
  - 若需要分页，给出分页方案并说明合并行如何处理
  - 若暂不分页，需要在 Issue 结论中说明原因和替代处理方式
- 为专业级计算看板支撑课程表增加表格上下滚动：
  - 目标页面为专业级计算看板中的支撑课程状态明细表
  - 表格需要设置稳定高度或最大高度，支持纵向滚动
  - 表头应保持可读，避免支撑课程较多时撑长整个页面
- 为专业级达成度结果查看中的课程级状态明细增加表格上下滚动：
  - 保证课程级状态明细较多时页面仍可快速查看专业级结果
  - 不改变现有计算状态、阻断原因、解锁申请等字段口径

完成标准：

- 有毕业要求表是否分页的分析结论
- 有指标点表是否分页的分析结论
- 若毕业要求表或指标点表需要分页，给出可执行的前后端处理方案
- 若暂不分页，说明原因并给出滚动、高度限制或筛选增强等替代方案
- 专业级计算看板支撑课程表已支持上下滚动
- 专业级达成度结果查看中的课程级状态明细已支持上下滚动

  

### 3. `member/wzj`：基础数据-专业管理、基础数据-学院管理分页闭环开发

Issue 内容：

- 对应账号角色：**系统管理员**
- 本 Issue 必须遵守统一分页接口口径：
  - 前端查询参数统一携带 `pageNum`、`pageSize`
  - 后端列表查询接口接收分页参数，并基于筛选条件执行分页查询
  - 后端返回结构统一包含：
    - `records`：当前页数据
    - `total`：符合筛选条件的总记录数
    - `pageNum`：当前页码
    - `pageSize`：每页条数
  - 前端统一使用 Element Plus `el-pagination`，支持页码切换、每页条数切换和总数展示
  - 前端 `pageSize` 可选项统一设置为 `5, 10, 20, 50`
  - 查询、重置、新增、编辑、删除、启停后必须正确刷新当前分页数据
  - 保持现有动作式接口路径不变，分页接口命名统一采用 `listXxxByPage`，不另起资源式接口
- 负责基础数据-专业管理列表分页：
  - 前端在专业管理表格下方加入 Element Plus `el-pagination`
  - 查询参数携带 `pageNum`、`pageSize`
  - 后端专业列表接口接收分页参数并返回 `records`、`total`、`pageNum`、`pageSize`
  - 查询、重置、新增、编辑、删除、启停后正确刷新当前页或回到第一页
- 负责基础数据-学院管理列表分页：
  - 前端在学院管理表格下方加入 Element Plus `el-pagination`
  - 查询参数携带 `pageNum`、`pageSize`
  - 后端学院列表接口接收分页参数并返回统一分页结构
  - 删除当前页最后一条数据后，需要避免停留在空页
- 保持现有动作式接口路径风格，不新增资源式分页路径
- 与组长完成系统管理员账号下的分页联调

完成标准：

- 系统管理员可在专业管理列表使用分页查询
