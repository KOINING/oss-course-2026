## 八、功能测试流程

### 流程 A：教师端课程上下文与默认加载验证

#### 目标

验证教师只能看到自己负责的课程和教学班；模块 B 与模块 C 页面进入后默认加载一个课程 / 教学班，而不是空白页。

#### 步骤

1. 使用 `teacher_zhang` 登录系统。
2. 进入 `/course-objectives`。
3. 检查默认是否已选中一个课程和一个教学班。
4. 检查页面是否显示 `专业 + 年级 + 学期`。
5. 进入 `/assessment` 的 `成绩预览` 页签。
6. 再次检查默认教学班与上下文信息。
7. 切换教学班，确认上下文同步变化。

#### 预期结果

- 页面默认加载一个可操作的课程 / 教学班
- 仅显示当前教师负责的课程与教学班
- 上下文信息正确显示 `majorName / gradeYear / termCode`

### 流程 B：课程目标配置与回归验证

#### 目标

验证课程目标列表正常加载，新增 / 编辑后立即回显，不再出现历史 `400` 问题。

#### 步骤

1. 在 `课程目标配置` 页签选择课程和教学班。
2. 检查课程目标列表是否加载成功。
3. 新增 2 到 3 个课程目标。
4. 保存后观察列表是否立即刷新。
5. 编辑其中一个课程目标。
6. 尝试新增重复 `objectiveCode`。

#### 预期结果

- 不出现 `GET /api/course-objectives?... 400 Bad Request`
- 列表可正常回显
- 新增后立即刷新
- 重复 `objectiveCode` 被拦截

### 流程 C：内部权重 `w` 配置

#### 目标

验证页面只展示当前课程负责支撑的指标点，并按列校验 `Σw = 1.00`。

#### 步骤

1. 进入 `内部权重配置` 页签。
2. 检查是否默认加载一个课程和教学班。
3. 检查页面是否展示支撑指标点矩阵。
4. 确认只显示当前课程负责支撑的指标点。
5. 故意输入一列权重和不等于 `1.00` 的数据并保存。
6. 修正为合法值后再次保存。
7. 刷新页面检查回显。

#### 预期结果

- 首次进入页面即可显示矩阵
- 只显示本课程负责支撑的指标点
- 非法列和被拦截
- 合法配置可保存并回显

### 流程 D：考核点配置

#### 目标

验证考核点配置归属于模块 B，且课程目标下拉正常加载。

#### 步骤

1. 进入 `考核点配置` 页签。
2. 检查默认课程 / 教学班是否已带出。
3. 检查课程目标下拉框是否正常加载。
4. 新增多个考核点，填写名称、满分、绑定课程目标。
5. 编辑一个考核点。
6. 尝试保存非法满分。

#### 预期结果

- 页面在模块 B 下可独立完成考核点维护
- 课程目标下拉正常加载，不出现 `400`
- 合法考核点保存成功并回显
- 非法满分被拦截

### 流程 E：成绩预览与模板下载

#### 目标

验证成绩预览页签可展示动态模板结构和已保存成绩，并支持下载模板。

#### 步骤

1. 进入 `成绩预览` 页签。
2. 检查默认教学班和上下文是否已加载。
3. 检查顶部是否有 `计算并锁定` 按钮，位置应在课程标识右侧。
4. 检查表格固定列是否为 `学号 / 姓名`。
5. 检查动态列是否与当前考核点配置一致。
6. 点击下载模板并打开文件。

#### 预期结果

- 默认加载一个教学班
- 表格结构与当前考核点配置一致
- 模板可正常下载
- `计算并锁定` 按钮位于成绩预览页签顶部上下文栏

### 流程 F：成绩导入预校验

#### 目标

验证系统对成绩文件执行真实预校验，且错误能定位到具体行和具体问题。

#### 步骤

1. 进入 `成绩录入` 页签。
2. 上传 [score_import_valid_class2.xlsx](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/test-data/score_import_valid_class2.xlsx)。
3. 点击“预校验成绩文件”。
4. 检查成功行数、失败行数、`canSave`。
5. 上传 [score_import_invalid_rows_class2.xlsx](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/test-data/score_import_invalid_rows_class2.xlsx)。
6. 检查错误是否定位到具体行。
7. 上传 [score_import_invalid_header_class2.xlsx](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/test-data/score_import_invalid_header_class2.xlsx)。
8. 检查系统是否在文件级直接拦截。

#### 预期结果

- 合法文件预校验通过，允许保存
- 非法文件不允许保存
- 错误至少覆盖：
  - 模板列头不一致
  - 学号不属于当前教学班
  - 姓名与名单不一致
  - 成绩超出 `0 ~ 满分`
  - 文件内重复学号

### 流程 G：成绩保存与成绩预览回显

#### 目标

验证成绩保存后，当前教学班成绩预览区立即可见，不再只是上传成功但看不到结果。

#### 步骤

1. 对合法预校验结果点击“保存成绩”。
2. 观察教学班状态是否进入 `score_imported`。
3. 检查右侧“当前教学班成绩预览”是否刷新。
4. 点击“清空”。
5. 检查是否只清上传态，而不清右侧已保存成绩预览。

#### 预期结果

- 成绩保存后状态变为 `score_imported`
- 成绩预览区显示已保存的学生成绩
- “清空”只清上传文件和预校验结果，不清右侧已保存成绩

### 流程 H：课程级计算与锁定

#### 目标

验证系统按引擎规则依次计算 `Cij`、`C̄j`、`Ek`，并在计算完成后锁定教学班。

#### 步骤

1. 确认当前教学班所有学生、所有考核点成绩均已补齐。
2. 进入 `成绩预览` 页签。
3. 检查顶部 `计算并锁定` 按钮是否可点击。
4. 点击按钮执行课程级计算。
5. 检查教学班状态是否变为 `locked`。
6. 检查数据库中是否已落：
   - `student_objective_achievement`
   - `course_objective_achievement`
   - `course_indicator_achievement`

#### 预期结果

- 成绩未补齐时，不允许计算
- 补齐后可计算
- 计算完成后教学班状态变为 `locked`
- 三层课程级结果表均有数据

### 流程 I：课程目标级与课程级结果展示

#### 目标

验证教师端可以看到 `Cij`、`C̄j` 和 `Ek` 的可视化与表格结果。

#### 步骤

1. 课程级计算完成后停留在 `成绩预览` 页签。
2. 检查是否显示 `C̄j` 柱状图。
3. 检查是否显示 `Cij` 热力图。
4. 检查是否显示学生目标达成明细表。
5. 检查是否显示课程级指标点达成度 `Ek` 表格。

#### 预期结果

- `C̄j` 有图表展示
- `Cij` 有图表和明细表展示
- `Ek` 结果可见
- 图表与表格数据口径一致

### 流程 J：锁定后负向验证

#### 目标

验证教学班锁定后，教师不能继续覆盖原始成绩。

#### 步骤

1. 对已锁定教学班重新上传成绩文件。
2. 尝试再次保存成绩。
3. 观察页面提示和接口返回。

#### 预期结果

- 系统明确提示当前教学班已锁定
- 不允许继续修改或覆盖成绩

### 流程 K：专业级宏观看板与前置阻断

#### 目标

验证专业负责人可按 `专业 + 年级 + 学期` 查询看板，且未全部锁定时被阻断。

#### 步骤

1. 使用 `director_chen` 登录。
2. 进入 `宏观看板`。
3. 选择专业、年级、学期。
4. 检查课程状态列表与阻断原因。
5. 在存在未锁定课程时尝试触发专业级汇总。

#### 预期结果

- 看板能展示支撑课程状态
- 存在未锁定课程时，不允许执行专业级汇总
- 阻断原因明确

### 流程 L：专业级汇总与结果查看

#### 目标

验证全部支撑课程锁定后，专业级汇总可以执行并回显结果。

#### 步骤

1. 保证当前筛选范围内所有支撑课程均为 `locked`。
2. 触发专业级汇总。
3. 进入 `结果查看` 页签。
4. 检查指标点最终达成度结果。

#### 预期结果

- 汇总成功
- 数据落库到 `major_indicator_achievement`
- 页面可正确显示专业级结果

### 流程 M：`gradeYear` 隔离验证

#### 目标

验证同一专业不同 `gradeYear` 之间不串算。

#### 步骤

1. 为同一专业准备两个不同 `gradeYear` 的教学班。
2. 只完成其中一个年级的课程级计算。
3. 切换到另一个年级查看看板和结果。
4. 尝试对未完成年级执行专业级汇总。

#### 预期结果

- 两个年级状态独立
- 已完成年级不应影响未完成年级
- 专业级结果严格绑定 `majorId + gradeYear + termId`

### 流程 N：角色负向访问验证

#### 目标

验证非教师角色不能执行教师端配置动作，非专业负责人角色不能误触发专业级汇总。

#### 步骤

1. 使用 `admin` 或 `academic_wu` 尝试进入模块 B。
2. 使用 `teacher_zhang` 尝试执行专业级汇总。
3. 观察菜单、路由和接口返回。

#### 预期结果

- 权限边界清晰
- 无权限页面不暴露核心操作入口
- 无权限接口返回明确拒绝结果
