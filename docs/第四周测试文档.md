`课程目标 -> 内部权重 w -> 考核点 -> 动态成绩模板 -> 成绩导入预校验 -> 成绩保存 -> 课程级计算并锁定 -> 专业级前置校验 -> 专业级结果查看`

## 2. 当前项目定位

结合当前仓库实现，第四周测试按以下口径执行：

- 模块 A 已提供基础数据、专业、课程、教学班、学生名单、毕业要求、指标点与支撑矩阵基础支撑。
- 模块 B 由课程主讲教师维护：
  - 课程目标配置
  - 内部权重配置
  - 考核点配置
- 模块 C 分为两条角色链路：
  - 课程主讲教师：成绩预览、成绩录入、课程级计算与锁定
  - 专业负责人 / 教务管理员：宏观看板、专业级结果查看、解锁处理

第四周验收目标是“模块 B + 模块 C 首版闭环”，不是第五周报表导出。

## 5. 核心业务规则

### 5.1 年级与批次口径

第四周测试必须显式校验以下约束：

- `gradeYear` 表示培养方案版本 / 入学届别，不等于 `term`
- 模块 B 配置必须建立在当前课程所处的 `专业 + 年级` 语境下
- 模块 C 的成绩、课程级结果、专业级结果必须保持 `major + gradeYear + term` 一致
- 不允许不同年级的毕业要求、指标点、支撑矩阵、教学班成绩混算

### 5.2 计算规则

课程级和专业级计算按当前引擎口径验证：

- 学生课程目标达成度：`Cij`
- 班级课程目标平均达成度：`C̄j`
- 课程级毕业要求指标点达成度：`Ek`
- 专业级全局达成度：`Gk`

当前展示口径统一为：

- 使用小数展示
- 保留 4 位小数
- 不使用百分数

### 5.3 权重约束

- 对同一指标点，课程内部权重满足：`Σw = 1.0`
- 对同一指标点，宏观支撑矩阵总权重满足：`ΣW = 1.0`

### 5.4 锁定与解锁

- 教师点击 `计算并锁定` 后，课程级结果计算完成且教学班进入 `locked`
- 锁定后教师不能直接以“已锁定”状态继续提交最终结果
- 教师可提交解锁申请
- 专业负责人 / 教务管理员可执行解锁
- 解锁后允许后续修改成绩并重新计算

## 8. 详细测试流程

### 流程 A：角色入口与菜单验证

#### 目标

验证不同角色只能看到符合职责的入口，菜单命名与当前实现一致。

#### 操作步骤

1. 使用课程主讲教师账号登录。
2. 检查侧边菜单是否存在：
   - `课程目标与考核点`
   - `课程成绩与课程级计算`
3. 使用专业负责人 / 教务管理员账号登录。
4. 检查侧边菜单是否存在：
   - `达成度计算与看板`
5. 使用系统管理员账号登录。
6. 检查系统管理员端不显示：
   - `教学班管理`
   - `学生名单管理`
   - `组件预览`

#### 预期结果

- 菜单按角色准确显示
- 教师端与专业端菜单命名符合当前实现
- 系统管理员端不暴露第四周无关菜单

### 流程 B：教师端课程上下文验证

#### 目标

验证教师进入模块 B / C 后，只能在本人负责范围内选择课程与教学班，并能看到一致的上下文信息。

#### 操作步骤

1. 进入 `课程目标与考核点`。
2. 在课程和教学班选择区切换上下文。
3. 观察是否展示：
   - 教学班
   - 年级
   - 学年学期
   - 课程名称
4. 进入 `课程成绩与课程级计算`。
5. 检查 `成绩预览` 与 `成绩录入` 两个页签的上下文是否一致。

#### 预期结果

- 教师只能看到自己负责的课程与教学班
- 模块 B、模块 C 上下文一致
- 不需要额外独立“上下文页面”

### 流程 C：课程目标配置

#### 目标

验证教师可完成课程目标新增、查询、编辑、删除。

#### 操作步骤

1. 进入 `课程目标配置` 页签。
2. 选择课程和教学班。
3. 新增课程目标。
4. 检查列表是否刷新。
5. 编辑已有课程目标。
6. 删除未被依赖的课程目标。
7. 触发删除二次确认，检查按钮排列。

#### 预期结果

- 查询不报 400
- 新增成功后可立即在列表中核验
- 编辑结果能回显
- 删除确认弹层中：
  - `取消` 在左
  - `确认删除` 在右
  - 两个按钮同一行显示

### 流程 D：内部权重配置

#### 目标

验证内部权重页首次进入即可看到可配置矩阵，且按当前规则完成 `Σw = 1.0` 校验。

#### 操作步骤

1. 进入 `内部权重配置` 页签。
2. 选择课程和教学班上下文。
3. 检查页面是否展示课程目标 × 指标点矩阵。
4. 修改某列权重，使该列和不为 `1.0`。
5. 尝试保存。
6. 再将该列权重修正为 `1.0`。
7. 再次保存。

#### 预期结果

- 首次进入页面即可看到矩阵，不依赖“已有历史保存”
- 页面虽通过教学班反查上下文，但不应表现为“每个教学班单独配置一套 w”
- 当同一指标点列 `Σw != 1.0` 时禁止保存
- 修正后可保存成功

### 流程 E：考核点配置

#### 目标

验证考核点页签布局、课程目标下拉、考核点新增编辑删除正常。

#### 操作步骤

1. 进入 `考核点配置` 页签。
2. 检查页面布局是否与另外两个页签同层级、同卡片结构。
3. 选择课程与教学班。
4. 新增考核点，绑定课程目标。
5. 编辑已有考核点。
6. 删除无依赖考核点。

#### 预期结果

- 页面结构与 `课程目标配置`、`内部权重配置` 风格一致
- 课程目标下拉正常加载，不报 `/api/course-objectives` 错误
- 每个考核点只能绑定唯一课程目标

### 流程 F：成绩模板下载

#### 目标

验证教师端成绩模板下载文件名和模板结构正确。

#### 操作步骤

1. 进入 `成绩录入` 页签。
2. 点击下载模板。
3. 检查下载文件名。
4. 打开 Excel 文件，检查列头结构。

#### 预期结果

- 下载文件名为 `成绩模板.xlsx`
- 模板可正常被 Excel 打开
- 固定列包含：
  - 学号
  - 姓名
- 动态列与当前考核点配置一致

### 流程 G：成绩导入预校验

#### 目标

验证合法文件可通过预校验，非法文件可被准确拦截。

#### 操作步骤

1. 上传合法成绩文件。
2. 检查预览结果中的成功行数、失败行数和 `canSave` 状态。
3. 上传非法成绩文件。
4. 检查错误原因是否能定位到具体行和具体问题。

#### 预期结果

- 合法文件预校验通过，允许保存
- 非法文件被拦截，不允许保存
- 错误类型至少覆盖：
  - 模板列头不一致
  - 学号不属于当前教学班
  - 姓名与名单不一致
  - 成绩超出 `0 ~ 满分`
  - 文件内重复学号

### 流程 H：成绩保存与清空

#### 目标

验证成绩保存、右侧结果刷新与清空行为符合当前实现。

#### 操作步骤

1. 在 `成绩录入` 页签上传并通过预校验。
2. 点击保存。
3. 观察右侧结果区与 `成绩预览` 页签数据。
4. 点击清空。

#### 预期结果

- 保存成功后，成绩预览能看到最新成绩
- 清空时不仅清空上传文件，还应清空右侧导入结果与待保存状态

### 流程 I：成绩预览在线补录 / 修改

#### 目标

验证在未锁定阶段，教师可在成绩预览页进行简单查缺补漏和在线修改。

#### 操作步骤

1. 进入 `成绩预览` 页签。
2. 检查是否展示当前成绩表。
3. 在未锁定状态下，直接修改部分成绩。
4. 保存修改。
5. 再次刷新页面确认结果。

#### 预期结果

- 未锁定时可直接在线补录 / 改分
- 保存后结果持久化
- 与 `成绩录入` 页签数据保持一致

### 流程 J：课程级计算并锁定

#### 目标

验证教师端能完成 `Cij / C̄j / Ek` 计算，并在成功后自动锁定。

#### 操作步骤

1. 进入 `成绩预览` 页签。
2. 检查顶部是否存在 `计算并锁定` 按钮。
3. 在成绩未补齐时尝试计算。
4. 补齐全部学生 × 全部考核点成绩。
5. 确保 `Σw = 1.0`。
6. 点击 `计算并锁定`。
7. 刷新页面查看状态与结果。

#### 预期结果

- 按钮位于成绩预览页签顶部上下文栏
- 成绩未补齐时禁止计算
- 条件满足后可成功计算
- 计算后自动进入 `locked`
- 结果至少包含：
  - `Cij`
  - `C̄j`
  - `Ek`

### 流程 K：课程级结果展示

#### 目标

验证教师端能查看课程级结果看板，且展示口径正确。

#### 操作步骤

1. 在已计算并锁定的教学班中进入 `成绩预览`。
2. 检查是否展示：
   - 锁定标识
   - `C̄j` 图表 / 表格
   - `Cij` 明细
   - `Ek` 表格
3. 检查数值格式。

#### 预期结果

- 页面可区分是否锁定
- 锁定提示位于模板说明上方
- `目标级达成度`、`课程级指标点达成度` 使用小数，保留 4 位
- 不以百分数展示

### 流程 L：教师申请解锁

#### 目标

验证已锁定教学班下，教师可提交解锁申请。

#### 操作步骤

1. 在已锁定教学班进入 `成绩预览`。
2. 点击申请解锁。
3. 填写原因并提交。
4. 刷新页面查看申请状态。

#### 预期结果

- 已锁定状态下允许发起解锁申请
- 页面显示已提交的解锁原因
- 提示文案体现“后续需修改成绩重新计算”

### 流程 M：专业级计算看板

#### 目标

验证专业负责人 / 教务管理员端宏观看板能正确显示支撑课程状态，并在存在阻断态时禁止专业级计算。

#### 操作步骤

1. 使用专业负责人或教务管理员账号登录。
2. 进入 `专业级计算看板` 页签。
3. 选择专业和年级。
4. 检查相关支撑课程 / 教学班状态。
5. 选择包含阻断态班级的样例。
6. 检查是否允许执行专业级计算。
7. 选择完整闭环样例再次检查。

#### 预期结果

- 年级筛选生效，切换后看板数据变化
- 看板状态至少能区分：
  - 未提交
  - 已提交未计算
  - 已锁定
- 对当前实现而言，教师端点击计算后即自动锁定，因此 `已计算未锁定` 仅可视为兼容 / 异常阻断态，不应作为主流程常态
- 存在阻断态班级时，不允许执行专业级计算
- 只在全部相关支撑教学班满足要求时，才允许进入专业级结果链路

### 流程 N：专业级结果查看

#### 目标

验证专业级结果与当前毕业要求 / 指标点配置一致，且不存在脏结果误导。

#### 操作步骤

1. 进入 `专业级结果查看` 页签。
2. 选择完整闭环样例的专业和年级。
3. 检查结果是否存在。
4. 核对指标点数量。
5. 切换到存在阻断态的样例。

#### 预期结果

- 仅完整闭环样例允许存在专业级结果
- 阻断态样例不应误显示“结果已生成”
- 指标点数量与当前毕业要求-指标点配置一致
- `Gk` 以小数展示，保留 4 位

### 流程 O：管理端解锁处理

#### 目标

验证专业负责人 / 教务管理员可处理教师的解锁申请。

#### 操作步骤

1. 在宏观看板或相关管理操作区查看解锁申请。
2. 对指定教学班执行解锁。
3. 刷新教师端页面。
4. 检查教师是否恢复可修改成绩状态。
5. 检查课程级结果是否需要重新计算。

#### 预期结果

- 管理端可以看到待处理解锁申请
- 解锁后教师端可再次修改成绩
- 后续需重新执行课程级计算并锁定

### 流程 P：年级隔离回归

#### 目标

验证不同专业、不同年级数据不会串线。

#### 操作步骤

1. 分别选择：
   - 计算机科学与技术 2022级
   - 计算机科学与技术 2023级
   - 软件工程 2022级
   - 软件工程 2023级
2. 检查毕业要求、指标点、支撑课程、教学班与结果。
3. 对不同年级样例分别查看课程级结果与专业级结果。

#### 预期结果

- 不同年级的毕业要求 / 指标点配置分离
- 不同年级课程级结果不混算
- 不同年级专业级结果不串线

## 9. 阻断规则

出现以下情况时，应停止后续测试并先修复：

- 模块 B 任一主配置页签无法正常查询或保存
- 内部权重 `Σw != 1.0` 仍能保存
- 考核点无法绑定课程目标
- 成绩模板下载文件损坏
- 合法成绩文件无法通过预校验
- 成绩未补齐却可直接执行计算
- 锁定后仍可绕过流程直接写入最终结果
- 存在阻断态教学班时，专业级结果仍显示已生成

## 10. 执行后验收标准

第四周测试通过，至少应满足以下条件：

1. 教师可完成模块 B 全链路配置：
   - 课程目标
   - 内部权重 `w`
   - 考核点

2. 教师可完成模块 C 课程级闭环：
   - 下载模板
   - 导入成绩
   - 预校验
   - 保存成绩
   - 在线补录 / 修改
   - 计算并锁定
   - 查看 `Cij / C̄j / Ek`

3. 专业负责人 / 教务管理员可完成专业级前置校验：
   - 看懂宏观看板
   - 识别阻断态
   - 查看专业级结果
   - 处理解锁申请

4. 年级隔离成立：
   - `major + gradeYear + term` 口径不混乱

5. 展示口径统一：
   - 达成度一律按小数显示
   - 保留 4 位小数
