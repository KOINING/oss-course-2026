# 第四周测试文档

## 一、文档目的

本文档用于指导第四周功能联调与验收测试，覆盖模块 B、模块 C 以及第四周新增的年级隔离链路。

第四周测试不再重复验证第二周、第三周已经稳定通过的基础 CRUD 和基础导入能力，重点验证以下闭环是否真实可用：

- 教师端课程上下文读取
- 课程目标配置
- 课程目标对指标点内部权重 `w` 配置
- 考核点配置
- 动态成绩模板预览与下载
- 原始成绩导入预校验与保存
- 课程级达成度计算与锁定
- 专业级宏观看板、前置阻断、专业级汇总与结果查看
- `majorId + gradeYear + termId` 口径隔离

## 二、第四周测试范围

### 1. 角色范围

- **课程主讲教师**：第四周主测试角色，负责模块 B 和模块 C 阶段一闭环
- **专业负责人**：负责模块 C 阶段二，验证宏观看板、专业级汇总、专业级结果查看
- **教务管理人员**：参与专业级链路联调，辅助验证教学班、学生名单和状态前提
- **系统管理员**：仅用于角色边界和菜单访问负向验证，不作为第四周主业务操作角色

### 2. 功能范围

- 模块 B：课程目标、内部权重 `w`、考核点
- 模块 C：模板预览/下载、成绩导入预校验、成绩保存、课程级计算、专业级汇总、结果查看
- 第四周数据库补充：`student_objective_achievement` 中间结果表
- 第四周年级链路：同专业不同 `gradeYear` 不串算

### 3. 不在本轮重点范围内

- 第二周、第三周已完成的基础数据管理细节回归
- 第五周报表导出、穿透式台账导出
- 复杂 UI 打磨、展示层美化

## 五、测试数据准备

### 1. 推荐业务上下文

建议选取一门已经在支撑矩阵中完成 `W` 配置的课程，且该课程满足：

- 已存在合法教学班
- 已存在学生名单
- 已关联到某专业某 `gradeYear`
- 该专业当前 `gradeYear` 下已有毕业要求、指标点和支撑矩阵数据

### 2. 成绩测试文件

第四周测试不建议手工编造列头，统一使用系统下载模板生成测试文件。

建议准备 3 份文件：

1. **合法文件**
   - 从系统模板下载后填写完整成绩
2. **非法文件 A：模板列头错误**
   - 修改一个考核点列名或课程目标行
3. **非法文件 B：成绩或学生信息错误**
   - 包含不属于当前教学班的学号
   - 或某列成绩大于满分
   - 或文件内重复学号

## 六、功能测试流程

### 流程 A：教师端课程上下文与入口验证

#### 目标

验证教师只能看到自己负责的课程和教学班，并且页面能正确显示 `专业 + 年级 + 学期` 上下文。

#### 步骤

1. 使用 `teacher_zhang` 登录系统。
2. 进入第四周教师端入口页。
3. 打开课程目标配置页。
4. 查看课程选择区、教学班选择区、当前上下文信息。
5. 切换不同教学班，观察 `majorName`、`gradeYear`、`termCode` 是否同步变化。

#### 预期结果

- 仅显示当前教师有权限操作的课程/教学班
- 页面可明确显示当前专业、年级、学期
- 不出现空上下文或串用其他教师课程数据

### 流程 B：课程目标配置

#### 目标

验证课程目标可新增、编辑、删除，并且同一课程内目标编码可校验。

#### 步骤

1. 在教师端选择一门目标课程。
2. 新增 2 到 3 个课程目标，填写目标编号与描述。
3. 尝试新增重复 `objectiveCode`。
4. 编辑其中一个课程目标描述。
5. 尝试删除一个未被后续数据引用的课程目标。

#### 预期结果

- 课程目标可以正常保存和回显
- 同一课程内重复 `objectiveCode` 被拦截
- 编辑后数据可重新查询到
- 删除逻辑符合后端约束

### 流程 C：内部权重 `w` 配置

#### 目标

验证课程目标对指标点的内部权重配置可保存，并按指标点列完成 `Σw = 1.0` 校验。

#### 步骤

1. 进入内部权重配置页。
2. 选择当前课程对应的指标点集合。
3. 为每个课程目标配置对指标点的 `w`。
4. 先故意录入一组列和不等于 `1.0` 的数据并保存。
5. 再修正为合法值并保存。

#### 预期结果

- 非法权重配置被明确提示
- 合法配置可以保存成功
- 刷新页面后权重能正确回显

### 流程 D：考核点配置

#### 目标

验证考核点可以维护，并且每个考核点只能绑定一个课程目标，满分必须大于 0。

#### 步骤

1. 进入考核点配置页。
2. 新增多个考核点，例如平时作业、实验、期末题组。
3. 为每个考核点填写名称、满分并绑定课程目标。
4. 尝试保存满分为 0 或空值的考核点。
5. 尝试录入无意义的重复考核点名称。

#### 预期结果

- 合法考核点保存成功
- 非法满分被拦截
- 绑定关系可以回显
- 重复或异常数据能得到业务提示

### 流程 E：动态成绩模板预览与下载

#### 目标

验证模板列头由当前考核点配置动态生成，并正确显示固定列、满分行、课程目标行。

#### 步骤

1. 在教师端选择教学班。
2. 点击模板预览。
3. 检查固定列是否为 `学号 | 姓名`。
4. 检查动态列是否与当前考核点一致。
5. 检查第二行满分、第三行课程目标编号。
6. 点击下载模板并打开文件。

#### 预期结果

- 预览结构与下载文件一致
- 动态列数量、名称、满分和课程目标编号均正确
- 未完成课程目标/权重/考核点前，系统阻止模板生成

### 流程 F：成绩导入预校验

#### 目标

验证系统能对成绩文件执行真实预校验，并区分成功行与失败行。

#### 步骤

1. 上传合法成绩文件。
2. 检查预览结果中的成功行数、失败行数和 `canSave` 状态。
3. 上传“模板列头错误”文件。
4. 上传“学生或成绩错误”文件。
5. 检查错误原因是否能定位到具体行和具体问题。

#### 预期结果

- 合法文件预校验通过，允许保存
- 非法文件被拦截，不允许保存
- 错误类型至少覆盖：
  - 模板列头不一致
  - 学号不属于当前教学班
  - 姓名与名单不一致
  - 成绩超出 `0 ~ 满分`
  - 文件内重复学号

### 流程 G：成绩保存与状态流转

#### 目标

验证成绩保存成功后，教学班状态进入 `score_imported`。

#### 步骤

1. 对合法预校验结果点击保存。
2. 重新进入成绩导入页。
3. 查看当前教学班计算状态标签。
4. 检查是否仍允许重复上传未锁定数据。

#### 预期结果

- 成绩保存成功
- 当前教学班状态变为 `score_imported`
- 页面状态与后端状态一致

### 流程 H：课程级计算与锁定

#### 目标

验证系统能完成课程级计算，落库学生级/课程目标级/课程指标点级结果，并将教学班状态更新为 `locked`。

#### 步骤

1. 在 `score_imported` 状态下点击课程级计算。
2. 等待计算结果返回。
3. 查看页面返回的课程目标达成度、课程指标点达成度。
4. 再次进入成绩导入页。
5. 观察是否进入锁定状态。

#### 预期结果

- 课程级计算成功
- 数据至少落库到：
  - `student_objective_achievement`
  - `course_objective_achievement`
  - `course_indicator_achievement`
- 当前教学班状态更新为 `locked`
- 锁定后教师不能继续修改原始成绩

### 流程 I：锁定后负向验证

#### 目标

验证锁定后教师端无法继续导入或覆盖成绩。

#### 步骤

1. 在已锁定教学班重新上传成绩文件。
2. 尝试再次保存成绩。
3. 观察页面提示和接口返回。

#### 预期结果

- 系统明确提示当前教学班已锁定
- 不允许继续修改成绩

### 流程 J：专业级宏观看板与前置阻断

#### 目标

验证专业负责人可以按 `专业 + 年级 + 学期` 查看看板，并在课程未全部锁定时被阻断。

#### 步骤

1. 使用 `director_chen` 登录。
2. 进入宏观看板页。
3. 选择某专业、某年级、某学期。
4. 观察支撑课程列表及状态。
5. 在至少一个课程未锁定时尝试触发专业级汇总。

#### 预期结果

- 看板能展示课程列表、状态和阻断原因
- 当存在未锁定课程时，不允许执行专业级汇总
- 阻断原因明确，不是泛化报错

### 流程 K：专业级汇总与结果查看

#### 目标

验证所有课程锁定后，专业级汇总可以执行，结果可以回显。

#### 步骤

1. 保证当前筛选范围内所有支撑课程均为 `locked`。
2. 触发专业级汇总。
3. 进入结果查看页。
4. 查看指标点最终达成度列表。

#### 预期结果

- 汇总成功
- 数据落库到 `major_indicator_achievement`
- 结果查看页可以读取并展示当前专业、年级、学期下的专业级结果

### 流程 L：`gradeYear` 隔离验证

#### 目标

验证同一专业不同 `gradeYear` 之间不串用课程、教学班和汇总结果。

#### 步骤

1. 为同一专业准备两个不同 `gradeYear` 的教学班。
2. 分别导入并计算其中一个年级的数据。
3. 在宏观看板切换到另一个年级。
4. 检查看板课程状态和专业级结果。
5. 尝试对未准备完成的年级触发汇总。

#### 预期结果

- 两个年级的课程状态彼此独立
- 一个年级已完成计算，不应让另一个年级直接通过专业级前置校验
- 专业级结果必须严格绑定到 `majorId + gradeYear + termId`

### 流程 M：角色负向访问验证

#### 目标

验证非教师角色不能执行教师端配置动作，非专业负责人角色不能误触发专业级汇总。

#### 步骤

1. 使用 `admin` 或 `academic_wu` 尝试进入教师端模块 B 页面。
2. 使用 `teacher_zhang` 尝试直接执行专业级看板汇总操作。
3. 观察菜单和接口返回。

#### 预期结果

- 角色访问边界清晰
- 无权限页面不应误暴露主操作入口
- 无权限接口返回明确拒绝结果

## 九、第四周验收通过标准

第四周验收建议至少满足以下条件：

- 教师端可以完成课程目标、内部权重 `w`、考核点的真实配置
- 系统可基于当前配置生成并下载动态成绩模板
- 成绩导入具备真实预校验能力，不是占位实现
- 成绩保存后教学班状态可进入 `score_imported`
- 课程级计算执行成功并进入 `locked`
- 锁定后教师端不能继续直接修改成绩
- 专业级看板可以正确阻断未满足前置条件的汇总
- 所有支撑课程锁定后，专业级汇总可以执行并可查看结果
- 同专业不同 `gradeYear` 不串算
- 数据库已补齐 `student_objective_achievement`

## 十、一句话总结

第四周测试的核心，不是单独验证某一个页面或某一个接口，而是验证“课程目标配置 -> 内部权重 `w` -> 考核点 -> 模板 -> 成绩导入 -> 课程级计算 -> 专业级汇总 -> 年级隔离”这条业务链是否已经真正闭环。
