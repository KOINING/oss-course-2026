# 第四周测试文档

## 一、文档目的

本文档用于第四周功能联调、回归测试与阶段验收，依据以下内容编写：

- [软件需求规格说明书.md](C:\Users\32484\Desktop\开源软件通识\oss-course-2026\docs\软件需求规格说明书.md)
- 第四周整改后的当前前后端实现
- 当前服务器数据库部署现状

第四周测试的核心不是重复第二周、第三周已经稳定通过的基础 CRUD，而是验证以下业务链是否已经真实闭环：

1. 主讲教师完成课程目标配置、内部权重 `w` 配置、考核点配置。
2. 系统基于模块 B 配置生成动态成绩模板，并支持成绩导入预校验与保存。
3. 系统完成课程级达成度计算、锁定，并支撑专业级汇总。
4. 同一专业下不同 `gradeYear` 的课程、教学班、课程级结果和专业级结果不会串算。

## 二、第四周需求边界

根据需求规格说明书，第四周测试重点覆盖以下范围：

### 1. 模块 B：课程目标与考核点

- **B-1 课程目标配置**
  - 教师维护本课程的课程目标
- **B-2 内部权重分配**
  - 系统自动读取模块 A 的宏观支撑矩阵
  - **仅向教师透出本课程负责支撑的指标点**
  - 教师配置课程目标到指标点的内部权重 `w`
  - 系统按指标点维度校验 `Σw = 1.0`
- **B-3 考核点细分与映射**
  - 教师拆分具体考核点
  - 为每个考核点录入满分
  - 每个考核点绑定到唯一课程目标

### 2. 模块 C：成绩录入与课程级计算

- 模板预览与下载
- 成绩导入预校验
- 成绩保存
- 课程级达成度计算
- 教学班锁定

### 3. 模块 C：专业级汇总与结果查看

- 宏观看板
- 专业级汇总前置阻断
- 专业级达成度结果查看
- `majorId + gradeYear + termId` 维度隔离

### 4. 不属于第四周主测试范围

- 第五周报表导出和穿透式台账导出
- 复杂界面样式优化
- 非第四周主链路的历史页面重构

## 八、功能测试流程

### 流程 A：教师端课程上下文与入口验证

#### 目标

验证教师只能看到自己负责的课程和教学班，页面可以正确显示 `专业 + 年级 + 学期` 上下文。

说明：本项是模块 B 和模块 C 页面内的上下文验证，不需要单独拆一个“课程上下文页面”。

#### 步骤

1. 使用 `teacher_zhang` 登录系统。
2. 进入 `课程目标与考核点` 页面。
3. 查看课程选择区、教学班选择区和上下文信息。
4. 切换不同教学班。
5. 观察 `majorName`、`gradeYear`、`termCode` 是否同步变化。

#### 预期结果

- 仅显示当前教师有权限操作的课程和教学班
- 页面明确显示当前专业、年级、学期
- 不出现空上下文、错误上下文或其他教师课程数据

### 流程 B：课程目标配置与 400 回归验证

#### 目标

验证课程目标页在选择课程和教学班后可以正常加载，新增后能够即时刷新回显。

#### 步骤

1. 进入 `课程目标配置` 页签。
2. 选择一门课程和一个教学班。
3. 观察页面是否正常加载课程目标列表。
4. 新增 2 到 3 个课程目标。
5. 保存后观察列表是否自动刷新。
6. 尝试新增重复 `objectiveCode`。
7. 编辑一个课程目标描述。

#### 预期结果

- 选择课程和教学班后，不出现  
  `GET /api/course-objectives?... 400 Bad Request`
- 课程目标列表可以正常回显
- 新增成功后，列表立即刷新可见
- 同一课程内重复 `objectiveCode` 被拦截
- 编辑后的数据可以重新查询到

### 流程 C：内部权重 `w` 配置

#### 目标

验证内部权重页按 B-2 口径工作：只展示本课程负责支撑的指标点，并按指标点维度校验 `Σw = 1.0`。

#### 步骤

1. 进入 `内部权重配置` 页签。
2. 选择课程和教学班。
3. 检查页面是否展示当前课程可配置的指标点矩阵。
4. 确认矩阵只包含本课程负责支撑的指标点。
5. 在尚未保存任何权重记录的情况下，确认页面仍能显示矩阵。
6. 为各课程目标配置内部权重 `w`。
7. 先故意录入一组某指标点列和不等于 `1.0` 的数据并保存。
8. 再修正为合法值并保存。
9. 刷新页面验证回显。

#### 预期结果

- 页面首次进入时即可加载矩阵，而不是空白页
- 只展示当前课程负责支撑的指标点
- 非法权重配置被明确提示
- 合法配置可保存成功
- 刷新后权重能正确回显

### 流程 D：考核点配置与课程目标下拉回归验证

#### 目标

验证考核点配置已归入模块 B，且课程目标下拉框能够基于当前课程正常加载。

#### 步骤

1. 进入 `考核点配置` 页签。
2. 选择课程和教学班。
3. 观察课程目标下拉框是否正常加载。
4. 新增多个考核点，例如平时作业、实验、期末题组。
5. 为每个考核点填写名称、满分并绑定课程目标。
6. 尝试保存满分为 `0` 或空值的考核点。
7. 重新进入页面检查回显。

#### 预期结果

- 不出现  
  `GET /api/course-objectives?courseId=... 400 Bad Request`
- 模块 B 页面内即可完成考核点配置
- 课程目标下拉框可正常加载并显示正确描述
- 合法考核点保存成功并可回显
- 非法满分被拦截

### 流程 E：模块 C 页面边界验证

#### 目标

验证模块 C 教师端页面只承担模板和成绩链路，不再承担考核点配置职责。

#### 步骤

1. 进入 `成绩录入和计算` 页面。
2. 查看可见页签和页面结构。
3. 确认是否仍存在 `考核点配置` 页签或入口。

#### 预期结果

- 模块 C 教师端只包含模板预览、成绩录入和计算相关内容
- 不再存在重复的 `考核点配置` 主入口

### 流程 F：动态成绩模板预览与下载

#### 目标

验证模板列头根据当前考核点配置动态生成，并正确展示固定列、满分行和课程目标行。

#### 步骤

1. 进入模块 C 教师端页面。
2. 选择教学班。
3. 点击模板预览。
4. 检查固定列是否为 `学号 | 姓名`。
5. 检查动态列是否与当前考核点一致。
6. 检查满分行与课程目标行。
7. 点击下载模板并打开文件。

#### 预期结果

- 预览结构与下载文件一致
- 动态列数量、名称、满分和课程目标编号均正确
- 当前课程目标、内部权重或考核点未完成配置时，系统阻止模板生成

### 流程 G：成绩导入预校验

#### 目标

验证系统对成绩文件执行真实预校验，并能返回明确的错误原因。

#### 步骤

1. 上传合法成绩文件。
2. 检查预览结果中的成功行数、失败行数和 `canSave` 状态。
3. 上传“模板结构错误”文件。
4. 上传“数据内容错误”文件。
5. 检查错误原因是否能定位到具体行和具体问题。

#### 预期结果

- 合法文件预校验通过，允许保存
- 非法文件被拦截，不允许保存
- 错误类型至少覆盖：
  - 模板列头不一致
  - 学号不属于当前教学班
  - 姓名与名单不一致
  - 成绩超出 `0 ~ 满分`
  - 文件内重复学号

### 流程 H：成绩保存、课程级计算与锁定

#### 目标

验证成绩保存后状态进入 `score_imported`，课程级计算完成后进入 `locked`，并完成结果落库。

#### 步骤

1. 对合法预校验结果点击保存。
2. 查看当前教学班状态。
3. 在 `score_imported` 状态下点击课程级计算。
4. 等待计算结果返回。
5. 查看课程目标达成度与课程指标点达成度。
6. 再次进入成绩页，确认状态是否为 `locked`。

#### 预期结果

- 成绩保存成功后，状态变为 `score_imported`
- 课程级计算成功后，状态变为 `locked`
- 至少完成以下结果层落库：
  - `student_objective_achievement`
  - `course_objective_achievement`
  - `course_indicator_achievement`

### 流程 I：锁定后负向验证

#### 目标

验证教学班锁定后，教师不能继续覆盖原始成绩。

#### 步骤

1. 在已锁定教学班重新上传成绩文件。
2. 尝试再次保存成绩。
3. 观察页面提示和接口返回。

#### 预期结果

- 系统明确提示当前教学班已锁定
- 不允许继续修改或覆盖成绩

### 流程 J：专业级宏观看板与前置阻断

#### 目标

验证专业负责人可以按 `专业 + 年级 + 学期` 查询看板，并在课程未全部锁定时被阻断。

#### 步骤

1. 使用 `director_chen` 登录。
2. 进入宏观看板页。
3. 选择某专业、某年级、某学期。
4. 观察支撑课程列表、状态和阻断原因。
5. 在至少一个课程未锁定时尝试触发专业级汇总。

#### 预期结果

- 看板能展示课程列表、状态和阻断原因
- 当存在未锁定课程时，不允许执行专业级汇总
- 阻断原因明确，不是泛化报错

### 流程 K：专业级汇总与结果查看

#### 目标

验证所有支撑课程锁定后，专业级汇总可以执行，结果可以回显。

#### 步骤

1. 保证当前筛选范围内所有支撑课程均为 `locked`。
2. 触发专业级汇总。
3. 进入结果查看页。
4. 查看指标点最终达成度列表。

#### 预期结果

- 汇总成功
- 数据落库到 `major_indicator_achievement`
- 结果页可以读取并展示当前专业、当前年级、当前学期下的专业级结果

### 流程 L：`gradeYear` 隔离验证

#### 目标

验证同一专业不同 `gradeYear` 之间不串用课程、教学班和汇总结果。

#### 步骤

1. 为同一专业准备两个不同 `gradeYear` 的教学班。
2. 仅导入并计算其中一个年级的数据。
3. 在宏观看板切换到另一个年级。
4. 检查看板课程状态和专业级结果。
5. 尝试对未准备完成的年级触发汇总。

#### 预期结果

- 两个年级的课程状态彼此独立
- 一个年级已完成课程级计算，不应让另一个年级直接通过专业级前置校验

## 十一、第四周验收通过标准

第四周验收建议至少满足以下条件：

1. 教师端可以完成课程目标、内部权重 `w`、考核点的真实配置。
2. 模块 B 的课程目标页、内部权重页、考核点页不再出现历史 `400` 错误。
3. 模块 C 教师端不再承担考核点配置职责。
4. 系统可基于当前配置生成并下载动态成绩模板。
5. 成绩导入具备真实预校验能力，不是占位实现。
6. 成绩保存后教学班状态进入 `score_imported`。
7. 课程级计算执行成功并最终进入 `locked`。
8. 锁定后教师不能继续修改成绩。
9. 专业级看板可以正确阻断不满足前置条件的汇总。
10. 所有支撑课程锁定后，专业级汇总可以执行并可查看结果。
11. 同专业不同 `gradeYear` 不串算。
12. 数据库已补齐 `student_objective_achievement`。

## 十二、一句话总结

第四周测试的核心不是验证若干页面是否能打开，而是验证“课程目标 -> 内部权重 `w` -> 考核点 -> 模板 -> 成绩导入 -> 课程级计算 -> 专业级汇总 -> 年级隔离”这条链路是否已经形成可联调、可回归、可验收的完整闭环。
