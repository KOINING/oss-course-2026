# 第二周至第八周总体任务规划

本文档用于统一第二周至第八周的项目推进节奏。当前时间点为**第六周**，课程开发与验收准备仅剩**第六周、第七周**两个任务周期，因此本文保留第二周至第五周作为历史任务基线，并将后续执行任务压缩到第六周和第七周完成。

本次规划基于以下文档同步调整：

- [软件需求规格说明书.md](./软件需求规格说明书.md)
- [系统总体架构设计.md](./系统总体架构设计.md)
- [第四周任务分配.md](./第四周任务分配.md)
- [第五周任务分配.md](./第五周任务分配.md)

本轮调整后的核心结论如下：

- **第六周：补齐主链路缺口，完成模块 A/B/C/D 全链路联调和缺陷修复**
- **第七周：完成部署、测试、文档、演示数据、答辩材料和最终版本固化**
- **第二周至第五周保留为历史任务基线，用于说明前置工作与当前冲刺任务的来源**
- **不再单独设置第八周开发任务，最终收口压缩到第七周完成**

这意味着：**第六周结束时系统必须能跑通可演示业务闭环；第七周结束时系统必须能支撑课程验收与答辩展示。**

---

## 一、规划依据与当前判断

### 1. 需求边界

根据《软件需求规格说明书》，平台主链路为：

1. 模块 A：基础数据、毕业要求、指标点、课程清单、教学班、学生名单、宏观支撑矩阵
2. 模块 B：课程目标、课程目标对指标点内部权重 `w`、考核点映射
3. 模块 C：动态成绩模板、原始成绩导入、课程级计算、专业级计算
4. 模块 D：课程级报表、专业级报告、穿透台账导出

剩余两周不再扩展需求规格说明书以外的功能，不新增问卷、异常预警、AI 辅助等范围外模块。

### 2. 当前项目真实起点

进入第六周时，项目已经具备：

- 登录、权限、角色菜单和基础系统骨架
- 模块 A 大部分页面与接口
- 课程、教学班、学生、毕业要求、指标点、支撑矩阵的主链路
- 模块 B、模块 C、模块 D 对应的数据表基础

第六周必须重点收口的是：

- 模块 B 的页面、接口和与模块 A 的数据联动
- 模块 C 的成绩模板、成绩导入、课程级计算、专业级汇总
- 模块 D 的课程级报表、专业级报告和穿透台账导出
- 面向“不同年级培养方案版本”的完整链路约束
- 演示数据、初始化 SQL、部署说明和测试记录

因此剩余两周的推进原则是：**优先保证可运行闭环，其次修复缺陷，最后补全文档和展示材料。**

## 二、跨模块数据约束：必须显式区分年级与学期

后续所有开发、测试、导入模板和报表导出，都必须严格区分两条维度：

- `term` / `学期`：表示教学运行周期，如 2025-2026-1
- `gradeYear` / `年级`：表示学生入学届别或培养方案版本，如 2022级、2023级

两者不能混用。

### 1. 年级字段的业务含义

- 年级用于标识某一届学生对应的培养方案版本
- 学期用于标识某一批教学班实际开课和计算发生的时间
- 系统中的配置对象和计算对象必须同时考虑这两条维度，但承担职责不同

### 2. 需要按年级生效的核心对象

- `graduation_requirement.grade_year`
- 指标点所属的毕业要求版本
- `course_major.grade_year`
- 支撑矩阵按 `majorId + gradeYear` 生效
- 教学班、成绩导入和后续计算链路必须继承或显式关联 `gradeYear`

### 3. 开发与验收口径

- 培养方案、毕业要求、指标点、必修课程、支撑矩阵都必须按 `专业 + 年级` 区分
- 模块 B 中课程目标与考核点配置，必须建立在当前课程所属 `专业 + 年级` 版本基础上
- 模块 C 中成绩导入和达成度计算，必须基于与教学班一致的年级口径
- 专业级结果以 `专业 + 年级` 为归档主体，以 `学期` 为结果快照或阶段性统计维度
- 任何页面、接口、导入模板和计算结果都不能把不同年级的课程、指标点或学生混算

## 三、第二周至第五周历史任务基线

第二周至第五周已经进入历史阶段，本节保留其规划内容，用于说明模块依赖关系和第六周冲刺任务来源。后续不再按这些周次重新安排开发时间。

## 第 2 周：项目底座与模块 A 第一阶段

### 本周目标

- 完成系统基础运行骨架与核心基础数据管理
- 完成毕业要求、指标点主数据第一版
- 从本周开始明确 `学期` 与 `年级` 两条维度

### 必须完成

- 角色、账号、权限和菜单稳定联调
- 基础字典管理：学年学期、学院、专业
- 毕业要求管理第一版
- 指标点管理第一版
- 项目接口、DTO、数据库字段命名收口

### 本周验收

- 管理员可维护基础字典和账号角色
- 专业负责人可维护毕业要求和指标点
- 文档中明确写出后续模块必须区分 `term` 与 `gradeYear`

---

## 第 3 周：模块 A 完整落地

### 本周目标

- 完成模块 A 全量主链路
- 为模块 B 和模块 C 提供稳定上游数据
- 建立按年级生效的培养方案与支撑矩阵基础

### 必须完成

- 课程管理、教学班管理、学生基础信息管理
- 课程清单导入
- 学生导入
- 教学班学生名单导入
- 宏观支撑矩阵配置
- 年级版本化基础：
  - 毕业要求按 `专业 + 年级`
  - 课程培养方案按 `专业 + 年级`
  - 支撑矩阵按 `专业 + 年级`

### 本周验收

- 教务管理人员可完成课程清单、学生、教学班学生名单导入
- 专业负责人可按专业和年级配置支撑矩阵
- 同一专业不同年级的数据在模块 A 中互不串线

---

## 第 4 周：模块 B + 模块 C 全量首版

### 本周目标

- 完成模块 B 与模块 C 的完整首版闭环
- 形成“课程目标配置 -> 动态成绩模板 -> 成绩导入 -> 课程级计算 -> 专业级汇总”的完整链路

### 必须完成

- 模块 B：课程目标配置、内部权重 `w`、考核点配置、考核点到课程目标映射
- 模块 C-1：按课程、教学班、考核点生成动态成绩模板并支持 `.xlsx` 导出
- 模块 C-2：原始成绩导入、导入预览、字段校验、学生校验、分值校验和重复记录校验
- 模块 C-3：学生个人课程目标达成度、教学班课程目标平均达成度、课程级指标点达成度计算
- 模块 C-4：按 `专业 + 年级` 进行专业级指标点达成度汇总，并校验支撑课程计算状态

### 本周验收

- 可为某专业某年级某门课配置课程目标、内部权重和考核点
- 可生成该教学班的动态成绩模板
- 可导入原始成绩并完成课程级计算
- 可在专业层按该年级完成指标点达成度汇总
- 同一专业两个年级并存时，配置、导入和计算互不串线

---

## 第 5 周：模块 D 报表与归档导出

### 本周目标

- 基于计算结果，完成课程级与专业级报表输出
- 完成认证支撑所需的穿透台账导出

### 必须完成

- 课程级评价报表导出
- 专业级达成度报告导出
- 穿透式台账导出
- 结果查询、筛选和导出权限控制

### 本周验收

- 课程级报表能读取课程级计算结果
- 专业级报告能读取专业级汇总结果
- 穿透台账可从专业指标点追溯到课程、课程目标、考核点和原始成绩

---

## 四、第六周任务安排：主链路补齐与全链路联调

### 本周目标

- 补齐模块 B/C/D 中影响业务闭环的缺口
- 完成从模块 A 到模块 D 的真实数据联调、计算校验和缺陷修复
- 形成可重复执行的演示链路，为第七周部署、文档和答辩准备提供稳定版本

### 必须完成

#### 1. 主链路缺口补齐

- 检查并补齐模块 B：
  - 课程目标配置
  - 课程目标对指标点内部权重 `w`
  - 考核点配置
  - 考核点到课程目标映射
  - 保存、回显、编辑和删除的基础闭环
- 检查并补齐模块 C：
  - 动态成绩模板导出
  - 原始成绩导入
  - 导入预览
  - 学生、字段、分值、重复记录校验
  - 课程级达成度计算
  - 专业级达成度汇总
- 检查并补齐模块 D：
  - 课程级评价报表导出
  - 专业级达成度报告导出
  - 穿透式台账导出
  - 结果查询、筛选和导出权限控制
- 统一前后端接口路径、字段命名、DTO 结构和错误提示口径

#### 2. 真实样例数据演练

- 准备至少 1 套完整演示数据：
  - 1 个专业
  - 1 个年级
  - 1 套毕业要求与指标点
  - 2 门以上支撑课程
  - 每门课至少 1 个教学班和若干学生成绩
- 使用演示数据完成从模块 A 到模块 D 的完整操作
- 保存演示数据初始化 SQL 或导入模板，避免演示前临时手工构造数据

#### 3. 计算公式与数据口径校验

- 校验课程目标达成度公式是否与需求规格说明书第 3.1 节一致
- 校验课程级指标点达成度公式是否与需求规格说明书第 3.2 节一致
- 校验专业级指标点达成度公式是否与需求规格说明书第 3.3 节一致
- 校验内部权重 `w` 和宏观支撑权重 `W` 的合计必须为 `1.0`
- 校验 `专业 + 年级` 口径贯穿毕业要求、指标点、课程清单、支撑矩阵、教学班、成绩导入和计算结果

#### 4. 跨角色流程联调

- 系统管理员：维护账号、角色、菜单和基础字典
- 教务管理人员：维护课程、教学班、学生名单，查看专业级结果并导出归档材料
- 专业负责人：维护毕业要求、指标点、支撑矩阵，触发或查看专业级计算
- 课程主讲教师：维护课程目标、内部权重、考核点，导入成绩并触发课程级计算

#### 5. 缺陷修复与稳定化

- 修复阻断主链路的前后端接口、权限、数据保存、导入导出和计算缺陷
- 修复不同年级、不同专业、不同教学班之间的数据串线问题
- 梳理初始化 SQL、增量 SQL、配置文件、Nginx 代理和部署依赖
- 形成第六周测试记录，记录已修复问题和遗留问题

### 本周验收

- 至少 1 条完整业务链路可稳定重复执行：
  - 管理基础数据
  - 配置毕业要求、指标点和支撑矩阵
  - 配置课程目标、内部权重和考核点
  - 导出成绩模板并导入原始成绩
  - 完成课程级计算和专业级汇总
  - 导出课程级报表、专业级报告或穿透台账
- 同一专业不同年级数据隔离验证通过
- 课程级和专业级计算结果可用手工样例复核
- 第七周可进入部署、测试、文档和演示版本固化阶段

## 五、第七周任务安排：部署、测试、文档与答辩准备

### 本周目标

- 修复第六周遗留的验收级问题
- 完成部署脚本、运行说明、操作手册、测试材料和演示数据收口
- 固化最终可展示版本，不再引入新的业务模块

### 必须完成

#### 1. 部署与运行收口

- 完成前端构建、后端打包、数据库脚本和 Nginx 配置联调
- 完成部署脚本与部署说明
- 完成运行说明，明确 JDK、Node.js、数据库、端口、配置文件和启动顺序
- 检查生产或演示环境账号、角色、菜单和基础数据是否可用

#### 2. 测试与问题修复

- 完成最终回归测试
- 完成第六周遗留问题修复
- 形成测试记录与问题修复跟踪表
- 对登录、权限、模块 A/B/C/D 主链路、导入导出、计算结果进行重点验证
- 确认剩余问题不影响最终展示和课程验收

#### 3. 文档与验收材料

- 完成主要角色操作手册
- 完成需求实现对照表
- 完成最终部署与运行说明
- 整理数据库脚本、演示数据、测试记录和项目说明文档
- 确保文档内容与当前代码实现一致

#### 4. 演示与答辩准备

- 固化演示数据和演示路径
- 整理演示账户和角色权限
- 准备答辩 PPT、演示脚本和关键截图
- 演练从登录到报表导出的完整闭环
- 冻结最终代码版本、数据库脚本和演示数据

### 本周验收

- 项目可按文档完成部署和启动
- 从登录到报表导出至少可演示 1 条完整业务闭环
- 文档、数据库脚本、代码版本和演示数据一致
- 测试记录完整，主要缺陷已关闭
- 系统可支撑课程验收与答辩展示

## 六、剩余两周交付标准

### 1. 第六周结束时的最低交付标准

- 模块 A/B/C/D 全链路可运行、可演示、可重复执行
- 数据口径、模板口径、报表口径一致
- 年级隔离和计算规则验证通过
- 第七周不再依赖大规模新功能开发，只处理缺陷、部署、文档和演示固化

### 2. 第七周结束时的最低交付标准

- 系统可演示
- 系统可部署
- 系统有操作文档、部署文档和测试记录
- 系统有固定演示数据和演示账户
- 系统可支撑课程验收与答辩展示

---

## 七、一句话总规划

**第二周至第五周保留为模块建设历史基线，第六周补齐模块 A/B/C/D 主链路并完成全链路联调，第七周完成部署、测试、文档、演示数据、答辩材料和最终版本固化。**
