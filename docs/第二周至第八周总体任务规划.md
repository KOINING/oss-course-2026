# 第二周至第八周总体任务规划

本文件用于指导项目从**第二周开始**到**第八周结束**的整体推进节奏。  
本版规划的核心调整是：

- **第 2 周到第 6 周完成全部核心开发任务**
- **第 4 周完成模块 B，同时完成模块 C 的 C-1 动态模板生成与导出**
- **第 5 周完成模块 C 的 C-2 原始成绩提交、C-3 课程级计算、C-4 专业级计算**
- **第 6 周专注完成模块 D 报表生成与底稿导出**

也就是说，平台的主体功能必须在**第七周开始之前**基本开发完成。

## 四、需求边界与模块映射

后续总体规划必须严格服从 [软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md) 中的系统边界，避免任务扩张。

### 2. 明确不做的内容

- 不做问卷等间接评价模块
- 不做成绩真实性异常预警
- 不做 AI 辅助分析或推荐
- 不做与主链无关的额外平台能力扩展

### 3. 周计划必须对应需求中的四个模块

- **模块 A：基础与宏观数据管理**

  - A-3 课程体系与名单导入
  - A-4 宏观支撑矩阵配置
- **模块 B：课程大纲与微观映射管理**
  - B-1 课程目标设定
  - B-2 内部权重分配
  - B-3 考核点细分与映射
- **模块 C：成绩录入与直接评价系统**
  - C-1 动态模板生成与导出
  - C-2 原始成绩提交
  - C-3 课程级达成度一键计算
  - C-4 专业级全局达成度计算
- **模块 D：报表生成与底稿导出**
  - D-1 课程级评价报表
  - D-2 专业级报告与台账导出

## 五、总体推进原则

### 1. 开发必须前置

第 7 周前必须完成全部核心功能开发，不能把计算、报表、导出拖到最后一周。

### 2. 依赖顺序必须严格

后续开发顺序固定为：

`基础字典 -> 毕业要求/指标点 -> 宏观支撑矩阵 -> 课程目标/内部权重/考核点 -> 动态成绩模板生成 -> 原始成绩导入 -> 课程级计算 -> 专业级计算 -> 报表导出`

### 3. 每周至少形成一个真实业务闭环

每周新增内容至少要满足：

- 页面可访问
- 接口可调用
- 数据可落库
- 角色可联调

### 4. Excel 模板口径必须尽早固定

由于平台上游数据不依赖外部系统接口，课程清单、学生名单和原始成绩都要通过手工录入或 Excel 模板导入，因此从第三周开始就要固定三类模板口径：

- **全专业课程清单导入模板**
  - 用途：教务管理人员批量导入专业课程清单，并建立课程与专业的归属关系
  - 推荐字段：`所属专业代码 | 课程代码 | 课程名称 | 学分 | 状态`
- **教学班学生名单导入模板**
  - 用途：教务管理人员导入教学班学生名单并建立学生与教学班关系
  - 推荐字段：`学号 | 姓名 | 专业代码 | 入学年份 | 教学班编号`
- **教学班原始成绩导入模板**
  - 用途：课程主讲教师导入某个教学班的各考核点原始成绩
  - 固定字段：`学号 | 姓名`
  - 动态字段：由系统根据当前教学班和考核点配置自动生成各考核点列

总体要求：

- 第三周确定并联调前两类模板
- 第四周生成并联调第三类模板，即教学班原始成绩导入模板
- 第五周基于第四周模板口径完成成绩 Excel 回导、Web 端预览补录和成绩落库
- 模板字段名、后端解析字段、数据库字段映射必须保持一致

### 5. 计算链路必须按两阶段触发落实

需求说明书已经明确计算触发机制，周计划不能把不同层级的计算混在一起：

- **阶段一：教师级触发**
  - 对应课程目标级达成度计算和课程级指标点达成度计算
  - 由课程主讲教师在成绩导入后触发
  - 结果只影响本课程，并进入“已锁定”状态
- **阶段二：全局级触发**
  - 对应专业级全局达成度计算
  - 由专业负责人或教务管理人员在全部支撑课程完成阶段一后统一触发
  - 结果供专业级报表与穿透式台账使用

### 6. 第 7 周开始禁止再开大坑

第 7 周开始只允许：

- 修 Bug
- 调整交互
- 补测试
- 补文档
- 稳定部署

不再开启新的核心业务模块。

## 六、角色推进规则

后续各周任务需要持续对齐 [软件需求规格说明书.md](/C:/Users/32484/Desktop/开源软件通识/oss-course-2026/docs/软件需求规格说明书.md) 中的 4 类角色，避免功能做出来后角色边界不清。

四类角色的周度主线应理解为：

- **系统管理员**：负责全局基础字典、账号与权限体系、系统初始化配置稳定
- **教务管理人员**：负责课程体系、教学班、学生名单、成绩导入、全局计算进度与最终报表导出
- **专业负责人**：负责毕业要求、毕业要求指标点、课程-毕业要求指标点宏观支撑矩阵、专业级计算
- **课程主讲教师**：负责课程目标、课程内部贡献权重 `w`、考核点、原始成绩录入、课程级计算

总体要求：

- 每一周都要说明“本周核心功能对应哪个角色”
- 页面、接口、联调链路和验收口径都尽量能映射到具体角色
- 如果某个角色在当周不是主操作角色，也应在说明中明确

### 角色与需求模块的固定映射

- **系统管理员**
  - 负责 A-1
  - 负责账号与角色管理
  - 不进入课程级和专业级计算主链
- **教务管理人员**
  - 负责 A-3
  - 参与 C-4
  - 负责 D-2 中的专业级归档报表导出
- **专业负责人**
  - 负责 A-2、A-4
  - 参与 C-4
  - 参与 D-2
- **课程主讲教师**
  - 负责 B-1、B-2、B-3
  - 负责 C-1、C-2、C-3
  - 负责 D-1

- 让宏观支撑矩阵具备可配置、可校验的第一版能力

## 第 4 周：模块 B 与 C-1 动态模板生成开发周

### 本周目标

- 完整做出课程主讲教师端的配置主链
- 在第 4 周结束前完成模块 B 的核心开发
- 提前完成 C-1 动态成绩模板生成与导出，使第五周可以直接进入成绩回导和计算

本周核心角色：

- **课程主讲教师**：课程目标、内部贡献权重 `w`、考核点、成绩模板生成与导出
- **专业负责人**：作为上游矩阵配置提供者参与联调校验
- **教务管理人员**：作为教学班和学生名单数据提供者参与模板生成联调
- **系统管理员**：不是本周主操作角色

### 本周必须完成

- B-1 课程目标设定

  定义本课程的若干教学目标（支持富文本/纯文本描述）

- B-2 内部权重分配第一版
  - 系统自动读取模块A中的宏观矩阵，**仅向教师透出**本课程所负责支撑的毕业要求指标点。
  - 教师设定每个课程目标对这些指标点的“内部贡献权重 ($w$)“。
  
  - 系统按指标点维度进行横向校验，权重之和必须等于 `1.0`。
  
- B-3 考核点细分与映射第一版
  - 教师在系统中拆分具体考核点（如：平时作业1、实验报告2、期末试卷大题3）。
  - 录入每个考核点的满分分值，并在下拉菜单中将其绑定至对应的唯一的“课程目标”。
  
- 模块 B 的权重校验与前置完整性校验
- C-1 动态模板生成与导出
  - 教师完成模块 B 后，系统根据其定义的考核点生成教学班原始成绩录入空模板
  - 模板固定字段为：`学号 | 姓名`
  - 模板动态字段由当前课程/教学班的考核点自动生成
  - 动态字段至少能追溯到：考核点名称、满分、绑定课程目标
  - 模板生成前必须校验：教学班已有学生名单、课程目标已配置、内部权重 `w` 已配平、考核点已配置
  - 支持教师下载 `.xlsx` 模板
  - 支持 Web 端模板预览，便于第五周成绩回导前确认字段口径

### 本周交付物

- 模块 B 页面与接口
- 教师端配置闭环
- C-1 动态成绩模板生成与下载接口
- 成绩模板 Web 预览页面或预览区域
- 教学班原始成绩导入模板字段说明
- 第 4 周接口清单
- 第 4 周联调记录

### 本周验收口径

- 课程主讲教师可以完成课程目标、内部权重、考核点的完整配置
- 每个指标点下内部贡献权重和可校验为 `1.0`
- 教师看不到与本课程无关的毕业要求指标点
- 模块 B 配置结果可直接供成绩模板生成和课程级计算使用
- 教师可以基于某个教学班生成并下载原始成绩录入模板
- 模板必须体现“固定字段 + 动态考核点字段”的结构
- 模板生成前置条件不满足时，系统必须给出明确阻断原因

## 第 5 周：模块 C 计算主链开发周

### 本周目标

- 从配置链推进到数据输入链
- 基于第四周已完成的动态模板，打通原始成绩回导、课程级计算和专业级计算
- 在第 5 周结束前完成模块 C 的 C-2、C-3、C-4

本周核心角色：

- **课程主讲教师**：原始成绩导入、Web 端成绩预览补录、课程级计算、课程锁定
- **教务管理人员**：辅助名单与班级数据一致性检查，参与专业级计算进度看板
- **专业负责人**：在所有支撑课程完成课程级计算后触发专业级全局计算
- **系统管理员**：不是本周主操作角色

### 本周必须完成

- C-2 原始成绩提交
  - 教师将第四周生成的 Excel 模板数据回导至系统
  - 后端解析成绩模板并校验学生、教学班、考核点和分值范围
  - 系统提供类似电子表格的 Web 前端预览界面，支持简单的数据查缺补漏操作
  - 合法成绩统一落库到 `student_assessment_score`
  - Web 补录和 Excel 回导必须使用同一套字段口径
  
- C-3 课程级达成度一键计算

  教师确认原始成绩无误后点击计算。

  - 系统按引擎规则，依次计算本课程的“目标级达成度”**以及**“课程级毕业要求指标点达成度”。
  - 计算完成后，系统将上述两级结果持久化至数据库，并将该课程的成绩单状态变更为“已锁定”。
- C-4 专业级全局达成度计算
  - 系统提供课程计算状态看板，展示相关支撑课程的计算状态
  - 当相关支撑课程全部完成阶段一计算并锁定后，专业负责人或教务管理人员可触发专业级计算
  - 系统提取各课程的课程级指标点达成度，结合宏观支撑矩阵 `W`，计算专业级指标点最终达成度
  - 专业级结果持久化，供第六周模块 D 报表读取

### 本周交付物

- 模块 C 成绩回导与预览补录页面
- 原始成绩导入接口
- 课程级计算接口与专业级计算接口
- 课程级结果页面
- 专业级计算状态看板与结果查询页面
- 第 5 周计算规则说明

### 本周验收口径

- 教师可以使用第四周模板导入成绩、校对成绩并触发课程级计算
- Excel 回导和 Web 补录写入同一套成绩数据结构
- 课程级计算完成后，相关课程成绩状态必须进入“已锁定”
- 课程级结果可以落库并被查询
- 课程状态能从未计算进入已锁定
- 专业负责人或教务管理人员可以查看课程计算状态，并在全部支撑课程锁定后触发专业级计算
- 专业级达成度结果可以落库并被查询
- 专业级计算只能在支撑课程全部完成阶段一计算后触发

## 第 6 周：模块 D 报表与底稿导出开发周

### 本周目标

- 在第 6 周内完成模块 D 的核心开发任务
- 基于第五周已经落库的课程级与专业级计算结果，完成课程级报表、专业级报告和穿透式台账导出
- 到本周结束时，平台核心开发任务视为完成

本周核心角色：

- **专业负责人**：查看专业级结果，导出专业级报告与穿透式台账
- **教务管理人员**：导出专业级归档报表和认证底稿
- **课程主讲教师**：查看课程级结果与课程评价报表
- **系统管理员**：不是本周主操作角色

### 本周必须完成

- D-1 课程级评价报表导出

  主讲教师可导出《课程目标达成情况评价表》PDF/Excel（包含班级单项平均分、各目标达成度明细）。

- D-2 专业级评价报表与穿透式台账导出

  教务管理员/专业负责人可导出全专业评价雷达图，以及支持认证专家查阅的“穿透式”Excel数据台账（展示从专业指标点层层向下追溯至某门课程、某个目标的得分明细）。
- 报表数据源校验
  - 课程级报表必须读取第五周落库的目标级达成度和课程级指标点达成度
  - 专业级报表必须读取第五周落库的专业级指标点达成度
  - 穿透式台账必须能够从专业指标点向下追溯到课程、课程目标、考核点和学生原始成绩

### 本周交付物

- 课程级评价报表导出
- 专业级评价报告导出
- 穿透式 Excel 台账导出
- 模块 D 页面与接口
- 第 6 周全链路联调记录

### 本周验收口径

- 系统可导出课程级和专业级关键报表
- 报表导出结果与第五周计算结果一致
- 穿透式台账能体现从专业指标点到课程、目标、考核点和原始成绩的追溯链路
- 课程主讲教师、专业负责人、教务管理人员只能导出其职责范围内的报表
- 到本周结束时，平台核心开发任务视为完成

## 九、按主线观察的压缩推进节奏

### 1. 业务功能主线

- 第 2 周：A-1、A-2
- 第 3 周：A-3、A-4
- 第 4 周：B-1、B-2、B-3、C-1
- 第 5 周：C-2、C-3、C-4
- 第 6 周：D-1、D-2
- 第 7 周：联调、测试、部署
- 第 8 周：验收、答辩、文档收口

### 2. 角色功能主线

- 第 2 周：系统管理员、专业负责人
- 第 3 周：教务管理人员、专业负责人
- 第 4 周：课程主讲教师，教务管理人员参与模板数据联调
- 第 5 周：课程主讲教师、专业负责人、教务管理人员
- 第 6 周：课程主讲教师、专业负责人、教务管理人员
- 第 7 周：四类角色全流程联调
- 第 8 周：四类角色全流程验收与展示

### 3. 技术稳定主线

- 每周至少 1 次中期联调
- 每周收口接口字段和返回结构
- 每周清理不应提交的构建产物
- 第 7 周前完成最小可复现运行链路
- 部署说明、运行说明、环境检查由组长统一牵头收口
- Excel 模板字段、数据库字段、前端表头定义每周同步校正一次

### 4. 数据一致性主线

- 第 2 周到第 3 周重点保证模块 A 表结构、实体类、DTO、前端表单一致
- 第 4 周重点保证课程目标、内部权重、考核点、原始成绩导入模板字段一致

- 第 7 周到第 8 周重点保证演示数据、导出文件和展示口径一致

### 5. 文档与验收主线

- 每周更新接口说明
- 每周更新联调问题清单
- 每周形成周验收结论
- 每周同步更新环境与运行说明
- 第 8 周完成最终文档定稿

## 十、一句话总规划

从第二周到第八周，项目的正确节奏应该是：

**第 4 周完成模块 B 并提前完成 C-1 动态模板，第 5 周完成 C-2/C-3/C-4 计算主链，第 6 周完成模块 D 报表导出，第 7 周起只做联调、测试、部署、文档和答辩准备。**

只要严格守住这个节奏，第 7 周之前完成开发任务是可实现的，后两周也才有足够空间把项目真正打磨成可验收、可展示、可答辩的完整平台。
