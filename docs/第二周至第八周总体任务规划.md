# 第二周至第八周总体任务规划

本文档用于统一第二周至第八周的项目推进节奏。  
本次重规划基于以下文档同步调整：

- [软件需求规格说明书.md](./软件需求规格说明书.md)
- [系统总体架构设计.md](./系统总体架构设计.md)
- [第四周任务分配.md](./第四周任务分配.md)

本轮调整后的核心结论如下：

- **第四周完成模块 B 和模块 C 全量首版**
- **第五周完成模块 D**
- **第六周不再新增核心功能，改为全链路联调、缺陷修复和稳定化**
- **第七周至第八周聚焦部署、文档、测试收口和答辩准备**

这意味着：**到第四周结束时，系统必须已经具备从课程目标配置到专业级达成度汇总的完整首版业务链路。**

---

## 一、规划依据与当前判断

### 1. 需求边界

根据《软件需求规格说明书》，平台的主链路为：

1. 模块 A：基础数据、毕业要求、指标点、课程清单、教学班、学生名单、宏观支撑矩阵
2. 模块 B：课程目标、课程目标对指标点内部权重 `w`、考核点映射
3. 模块 C：动态成绩模板、原始成绩导入、课程级计算、专业级计算
4. 模块 D：课程级报表、专业级报告、穿透台账导出

根据《系统总体架构设计》，项目采用前后端分离架构，数据库中已经预留了模块 B 和模块 C 的关键表结构，因此当前重心不是重新设计体系，而是按依赖顺序完成业务落地与联调。

### 2. 当前项目真实起点

截至当前阶段，项目已经具备：

- 登录、权限、角色菜单和基础系统骨架
- 模块 A 大部分页面与接口
- 课程、教学班、学生、毕业要求、指标点、支撑矩阵的主链路
- 模块 B、模块 C、模块 D 对应的数据表基础

仍然缺少的是：

- 模块 B 的真实页面与接口
- 模块 C 的成绩模板、成绩导入、课程级计算、专业级汇总
- 模块 D 的报表与归档导出
- 面向“不同年级培养方案版本”的完整链路约束

因此本次总体规划必须把**业务链路完成度**放在“页面数量”之前。

## 二、跨模块数据约束：必须显式区分年级与学期

后续所有周计划和开发任务，都必须严格区分两条维度：

- `term` / `学期`：表示教学运行周期，如 2025-2026-1
- `gradeYear` / `年级`：表示学生入学届别或培养方案版本，如 2022级、2023级

两者不能混用。

### 1. 年级字段的业务含义

- 年级用于标识某一届学生对应的培养方案版本
- 学期用于标识某一批教学班实际开课和计算发生的时间
- 系统中的配置对象和计算对象必须同时考虑这两条维度，但承担职责不同

### 2. 本项目中需要按年级生效的核心对象

- `graduation_requirement.grade_year`
- 指标点所属的毕业要求版本
- `course_major.grade_year`
- 支撑矩阵按 `majorId + gradeYear` 生效
- 教学班、成绩导入和后续计算链路必须继承或显式关联 `gradeYear`

### 3. 开发时必须遵守的口径

- 培养方案、毕业要求、指标点、必修课程、支撑矩阵都必须按 `专业 + 年级` 区分
- 模块 B 中课程目标与考核点配置，必须建立在当前课程所属 `专业 + 年级` 版本基础上
- 模块 C 中成绩导入和达成度计算，必须基于与教学班一致的年级口径；本系统中的教学班表示 `专业 + 年级 + 必修课程` 的课程评价单元
- 专业级结果以 `专业 + 年级` 为归档主体，以 `学期` 为结果快照或阶段性统计维度
- 任何页面、接口、导入模板和计算结果都不能把不同年级的课程、指标点或学生混算

## 三、第二周至第八周总体安排

## 第 2 周：项目底座与模块 A 第一阶段

### 本周目标

- 完成系统基础运行骨架与核心基础数据管理
- 完成毕业要求、指标点主数据第一版
- 从本周开始明确 `学期` 与 `年级` 两条维度

### 必须完成

- 角色、账号、权限和菜单稳定联调
- 基础字典管理：学年学期、学院、专业
- 毕业要求管理第一版
- 指标点管理第一版
- 项目接口、DTO、数据库字段命名收口

### 本周验收

- 管理员可维护基础字典和账号角色
- 专业负责人可维护毕业要求和指标点
- 文档中明确写出后续模块必须区分 `term` 与 `gradeYear`

---

## 第 3 周：模块 A 完整落地

### 本周目标

- 完成模块 A 全量主链路
- 为模块 B 和模块 C 提供稳定上游数据
- 建立按年级生效的培养方案与支撑矩阵基础

### 必须完成

- 课程管理、教学班管理、学生基础信息管理
- 课程清单导入
- 学生导入
- 教学班学生名单导入
- 宏观支撑矩阵配置
- 年级版本化基础：
  - 毕业要求按 `专业 + 年级`
  - 课程培养方案按 `专业 + 年级`
  - 支撑矩阵按 `专业 + 年级`

### 本周验收

- 教务管理人员可完成课程清单、学生、教学班学生名单导入
- 专业负责人可按专业和年级配置支撑矩阵
- 同一专业不同年级的数据在模块 A 中互不串线

---

## 第 4 周：模块 B + 模块 C 全量首版

### 本周目标

- 一次性完成模块 B 与模块 C 的完整首版闭环
- 形成“课程目标配置 -> 动态成绩模板 -> 成绩导入 -> 课程级计算 -> 专业级汇总”的完整链路

### 必须完成

#### 模块 B

- 课程目标配置
- 课程目标对指标点内部权重 `w`
- 考核点配置
- 考核点到课程目标映射

#### 模块 C-1

- 按课程/教学班/考核点生成动态成绩模板
- 模板预览与 `.xlsx` 导出

#### 模块 C-2

- 原始成绩导入
- 导入预览
- 字段、学生、分值、重复记录校验
- 成绩保存与幂等处理

#### 模块 C-3

- 学生个人课程目标达成度计算
- 教学班课程目标平均达成度计算
- 教学班课程级指标点达成度计算
- 课程级结果锁定

#### 模块 C-4

- 按 `专业 + 年级` 进行专业级指标点达成度汇总，学期仅作为兼容当前表结构的运行批次字段
- 汇总前校验支撑课程是否全部完成课程级计算
- 提供计算状态与进度查看

### 本周开发顺序

- 前半周完成模块 B 与 C-1/C-2 的数据入口
- 后半周完成 C-3/C-4 计算链路与联调
- 周末前至少跑通 1 条完整样例链路

### 本周验收

- 可为某专业某年级某门课配置课程目标、内部权重和考核点
- 可生成该教学班的动态成绩模板
- 可导入原始成绩并完成课程级计算
- 可在专业层按该年级完成指标点达成度汇总
- 同一专业两个年级并存时，配置、导入和计算互不串线

---

## 第 5 周：模块 D 报表与归档导出

### 本周目标

- 基于第四周已落库的计算结果，完成课程级与专业级报表输出
- 完成认证支撑所需的穿透台账导出

### 必须完成

- 课程级评价报表导出
- 专业级达成度报告导出
- 穿透式台账导出
- 结果查询、筛选和导出权限控制

### 本周验收

- 课程级报表能读取课程级计算结果
- 专业级报告能读取专业级汇总结果
- 穿透台账可从专业指标点追溯到课程、课程目标、考核点和原始成绩

---

## 第 6 周：全链路联调与稳定化

### 本周目标

- 不再新增核心功能

### 必须完成

- 计算公式校验
- 跨角色流程联调
- 缺陷修复
- 年级隔离验证
- 初始化 SQL、增量 SQL 和部署依赖梳理

### 本周验收

- 至少 1 条完整业务链路可稳定重复执行
- 同一专业不同年级数据隔离验证通过
- 主要问题已从“缺功能”收敛为“修缺陷和优化”

## 四、总体交付标准

### 1. 第四周结束时的最低交付标准

- 模块 B 全量首版完成
- 模块 C 全量首版完成
- 至少 1 条完整链路跑通：
  - 某专业某年级
  - 某门课程
  - 某教学班
  - 某批学生成绩
  - 课程级结果
  - 专业级结果

### 2. 第六周结束时的最低交付标准

- 模块 A/B/C/D 全链路可联调
- 数据口径、模板口径、报表口径一致
- 年级隔离和计算规则验证通过

### 3. 第八周结束时的最低交付标准

- 系统可演示
- 系统可部署
- 系统有文档
- 系统有测试记录
- 系统可支撑课程验收与答辩

---

## 五、一句话总规划

**第二周和第三周完成模块 A 及其年级版本化基础，第四周完成模块 B 和模块 C 全链路首版，第五周完成模块 D，第六周做全链路联调与稳定化，第七至第八周完成部署、文档、测试收口和答辩准备。**
