# 第四周整改 - 第三阶段专业级闭环说明

## 阶段目标

完成“宏观看板 -> 前置校验 -> 专业级汇总 -> 结果落库 -> 结果读取”的专业侧闭环，并把 `majorId + gradeYear + termId` 作为专业级主筛选维度真正贯穿到代码中。

## 本阶段已完成内容

### 1. `gradeYear` 贯穿专业级汇总主链

- `MajorCalcRequest` 新增 `gradeYear`。
- `MajorIndicatorAchievement` 实体补上 `gradeYear` 字段。
- 专业级汇总现在按以下条件定位范围：
  - `majorId`
  - `gradeYear`
  - `termId`
- 汇总结果保存时也按 `majorId + gradeYear + termId + ipId` 维度写入和更新。

### 2. 专业级看板查询接口补齐

新增 `/api/assessment` 下三组接口：

- `listMajorGradeYearTerms`
- `getMacroDashboard`
- `getMajorCalcResult`

看板接口会返回：

- 专业、年级、学期筛选项
- 当前筛选范围内的教学班列表
- 每个教学班的状态
- 阻断原因
- 是否允许执行专业级汇总
- 当前筛选范围是否已有专业级结果

### 3. 专业级汇总前置阻断真实生效

宏观看板现在不再靠前端规则猜测，而是后端按真实数据判断：

- 当前专业在该年级下是否有支撑课程
- 当前学期是否有教学班
- 当前范围内所有教学班是否都已 `locked`

只要有一个教学班未锁定，看板就会阻断专业级汇总。

### 4. 专业级结果读取补齐

- 结果页现在可以按 `专业 + 年级 + 学期` 查询
- 可直接读取专业级指标点达成度 `Gk`
- 若当前条件下没有汇总结果，会返回明确提示，而不是空白状态

### 5. 前端页面收口

#### 宏观看板

- 筛选条件改为必须同时选择：
  - 专业
  - 年级
  - 学期
- 新增“执行专业级汇总”按钮
- 新增专业级汇总结果表格

#### 结果查看页

- 不再只是静态说明卡片
- 改为可查询的结果页
- 同时展示：
  - 课程级状态明细
  - 专业级指标点结果

## 当前剩余风险

### 1. 本地编译环境仍未完成最终验证

- Maven 依赖下载问题已通过授权排除
- 但当前本地 Java 版本为 `17`
- 项目 `pom.xml` 要求 `21`

因此本轮无法在当前环境下完成后端编译验证。

### 2. 前端全量构建仍缺本地依赖

当前前端依赖未安装完成，无法在本地执行完整 `vite` 构建验证。

### 3. 课程级详细结果读取接口仍未单独展开

当前结果页优先收口了：

- 课程级状态明细
- 专业级最终结果

如果后续需要单独查看每个教学班的 `C̄j / Ek` 详细表，可以在第五周报表阶段继续补专用查询接口。

## 本阶段结论

第三阶段已经把第四周最关键的专业侧闭环补齐了：

- 看板不再是假状态
- 汇总不再串年级
- 结果不再只存在于数据库不可读
- 第五周报表已经有稳定的专业级输入口径
