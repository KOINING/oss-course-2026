# 第三周功能测试流程

## 一、文档目的

本文档用于第三周功能验收测试，依据以下两份文档并结合当前项目真实实现编写：

- [第三周任务分配.md](C:\Users\32484\Desktop\开源软件通识\oss-course-2026\docs\第三周任务分配.md)
- [软件需求规格说明书.md](C:\Users\32484\Desktop\开源软件通识\oss-course-2026\docs\软件需求规格说明书.md)

第三周测试的重点不是重复第二周的基础 CRUD，而是验证两条主业务链是否已经形成可用闭环：

1. 教务管理人员完成课程、教学班、学生主数据和导入链路。
2. 专业负责人完成毕业要求指标点前置数据检查，以及课程-指标点宏观支撑矩阵配置和 `W=1.0` 校验链路。

## 二、第三周需求边界

根据需求规格说明书与当前实现，第三周应重点覆盖以下范围：

### 1. 教务管理人员链路

- 课程管理
- 教学班管理
- 学生基础信息管理
- 数据导入
  - 课程清单导入
  - 学生基础信息导入
  - 教学班学生关联导入
- 导入结果预览与错误提示

### 2. 专业负责人链路

- 毕业要求与指标点查看/维护
- 支撑矩阵配置
- 宏观支撑权重 `W` 校验

### 3. 不属于第三周主链路的角色

- 系统管理员：负责系统初始化、基础字典、账号与角色管理，不参与第三周主业务操作。
- 课程主讲教师：不是第三周主操作角色，不应进入课程、教学班、学生主数据、数据导入和支撑矩阵配置主链。

## 七、功能测试流程

### 流程 A：系统管理员角色边界测试

#### 目标

验证系统管理员只承担系统初始化、字典管理和账号角色管理职责，不进入第三周主业务链。

#### 步骤

1. 使用 `admin / 123456` 登录。
2. 观察左侧菜单。
3. 进入 `基础数据` 页面。
4. 检查基础数据页可见内容。
5. 手工访问以下路径：
   - `/course-management`
   - `/teaching-class`
   - `/student-list`
   - `/data-import`
   - `/support-matrix`

#### 预期结果

1. 左侧菜单可见：
   - 首页
   - 基础数据
   - 系统管理
2. 左侧菜单不可见：
   - 课程管理
   - 教学班管理
   - 学生基础信息管理
   - 数据导入
   - 支撑矩阵配置
3. 基础数据页只展示管理员应维护的基础字典内容。
4. 手工访问第三周主业务路径时，应被路由守卫拦截回首页或无权限页。

### 流程 B：教务管理人员课程管理与课程清单导入

#### 目标

验证课程管理已从基础数据中拆分为独立菜单，并具备完整课程清单导入链路。

#### 步骤

1. 使用 `academic_wu / 123456` 登录。
2. 点击 `课程管理`。
3. 验证课程列表正常加载。
4. 进行课程查询。
5. 新增一条课程记录。
6. 编辑一条课程记录。
7. 点击页面上的课程导入入口，进入 `数据导入` 页。
8. 验证默认激活页签为 `课程清单导入`。
9. 下载课程导入模板。
10. 检查模板列头是否为：
    - `所属专业代码`
    - `课程代码`
    - `课程名称`
    - `学分`
    - `状态`
11. 上传合法课程清单文件并执行导入。
12. 查看导入结果预览。
13. 上传非法课程清单文件并执行导入。
14. 查看失败明细。

#### 预期结果

1. `课程管理` 为独立菜单页，不再混在基础数据页签内。
2. 课程列表、查询、新增、编辑都能调用真实接口。
3. 合法导入后，结果区显示：
   - 总记录数
   - 导入成功
   - 导入失败
4. 非法导入后，失败明细应能定位到具体错误。
5. 导入结果预览挂在导入主流程内，不是额外的脱离页。

### 流程 C：教务管理人员学生主数据链路

#### 目标

验证学生页现在只承担学生主数据维护职责，并具备学生基础信息批量导入入口。

#### 步骤

1. 使用 `academic_wu / 123456` 登录。
2. 点击 `学生基础信息管理`。
3. 检查页面摘要文案，确认本页只维护学生主数据。
4. 验证列表可正常查询、新增、编辑、删除或更新状态。
5. 点击 `前往批量导入学生基础信息`。
6. 跳转到 `数据导入` 页后，确认激活页签为 `学生基础信息导入`。
7. 下载模板。
8. 验证模板列头是否为：
   - `学号`
   - `姓名`
   - `专业代码`
   - `入学年份`
   - `学籍状态`
9. 上传合法学生基础信息文件并执行导入。
10. 返回学生基础信息管理页，确认新增学生可见。
11. 上传非法学生基础信息文件并执行导入。
12. 检查失败明细。

#### 预期结果

1. 学生页不再承担教学班学生关联导入入口。
2. 学生页工具栏只保留学生主数据相关操作。
3. 学生基础信息导入页签可正常导入学生主数据。
4. 合法导入后，新学生在学生基础信息管理页可见。
5. 非法导入后，应能返回学号重复、专业代码不存在、年份非法、状态非法等错误。
6. 学生主数据导入不会创建 `student_class` 关联。

### 流程 D：教务管理人员教学班管理与学生关联链路

#### 目标

验证教学班管理、教学班名单查看与教学班学生关联导入已经收敛为同一条业务链。

#### 步骤

1. 使用 `academic_wu / 123456` 登录。
2. 点击 `教学班管理`。
3. 验证教学班列表加载正常。
4. 检查教学班列表中是否可见业务编号 `classCode`。
5. 测试教学班查询、新增、编辑。
6. 点击某一教学班操作列的 `查看名单`。
7. 在抽屉中检查该教学班下学生关联列表。
8. 尝试移除一条学生关联。
9. 在教学班页顶部点击 `前往教学班学生关联导入`。
10. 跳转到 `数据导入` 页后，确认激活页签为 `教学班学生关联导入`。
11. 下载模板并检查列头：
    - `学号`
    - `姓名`
    - `专业代码`
    - `入学年份`
    - `教学班编号`
12. 上传合法教学班学生关联文件并执行导入。
13. 导入成功后，返回对应教学班并再次打开 `查看名单`。
14. 检查新增关联是否可见。
15. 上传非法教学班学生关联文件并执行导入。
16. 检查失败明细。

#### 预期结果

1. 教学班管理、名单查看、名单移除、名单导入应构成一条完整链路。
2. `查看名单` 抽屉只展示该教学班已关联学生。
3. 移除关联后列表即时刷新。
4. 合法导入成功后，在对应教学班名单中可以看到新增关联。
5. 非法导入应能准确提示：
   - 学号为空
   - 教学班编号不存在
   - 学号与姓名不匹配
   - 同一学生已在该教学班中
   - 模板内重复

### 流程 E：专业负责人毕业要求与指标点前置检查

#### 目标

验证支撑矩阵配置所需的毕业要求和指标点数据已经具备。

#### 步骤

1. 使用 `director_chen / 123456` 登录。
2. 点击 `毕业要求与指标点`。
3. 检查毕业要求列表。
4. 检查指标点列表。
5. 验证能否看到清晰的毕业要求-指标点对应关系。

#### 预期结果

1. 专业负责人可进入毕业要求与指标点页面。
2. 毕业要求与指标点数据可见。
3. 这些数据能够作为支撑矩阵配置的前置输入。

### 流程 F：专业负责人支撑矩阵配置与 `W` 校验

#### 目标

验证当前活跃链路 `supportmatrix.js + requirements/SupportMatrixView.vue` 已形成可用第一版闭环。

#### 步骤

1. 使用 `director_chen / 123456` 登录。
2. 点击 `支撑矩阵配置`。
3. 选择专业并查询。
4. 观察矩阵是否成功加载：
   - 行为课程
   - 列为指标点
5. 勾选若干课程-指标点支撑关系。
6. 为已勾选单元格输入权重 `W`。
7. 故意制造某一指标点列权重和不等于 `1.00`。
8. 点击 `保存矩阵`。
9. 观察校验提示。
10. 调整该列权重和为 `1.00`。
11. 再次点击 `保存矩阵`。
12. 刷新页面或重新查询，验证保存结果回显。

#### 预期结果

1. 支撑矩阵页使用当前活跃链路，不再走旧链路。
2. 查询后能加载真实矩阵数据。
3. 支撑关系可勾选，权重可输入。
4. 底部 `列权重合计（Σ）` 能实时反映列合计。
5. 某列权重和不为 `1.00` 时：
   - 页面有明确提示
   - 保存被阻止
6. 各列权重和都为 `1.00` 时：
   - 保存成功
   - 重新查询后可正确回显

### 流程 G：非主角色负向访问测试

#### 目标

验证第三周主业务页只对对应角色开放。

#### 步骤

1. 使用 `teacher_zhang / 123456` 登录。

3. 手工访问以下路径：
   - `/course-management`
   - `/teaching-class`
   - `/student-list`
   - `/data-import`
   - `/support-matrix`
4. 再使用 `admin / 123456` 验证一次第三周业务页访问边界。

#### 预期结果

1. 教师不应看到第三周主业务菜单。
2. 教师手工输入第三周主业务路径时也不应进入。
3. 管理员同样不应进入课程管理、教学班管理、学生基础信息管理、数据导入、支撑矩阵配置。
4. 权限收口应同时体现在：
   - 菜单显示
   - 路由访问
   - 接口访问

## 十一、一句话总结

第三周测试的核心不是验证若干页面是否能打开，而是验证以下两条闭环是否已经形成：

1. 教务管理人员：`课程管理 / 教学班管理 / 学生基础信息管理 / 三类数据导入`
2. 专业负责人：`毕业要求与指标点 / 支撑矩阵配置 / W 校验 / 保存回显`

只有这两条链都稳定打通，第三周任务才算真正完成，并能为后续课程目标、内部权重 `w`、成绩导入和达成度计算提供可靠前置条件。
